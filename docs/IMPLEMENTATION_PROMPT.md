# 기존 크루 프로토타입 UI 구조 개편 지시문

아래를 기존 프로토타입 코드가 있는 대화·프로젝트에 전달한다. 기능 명세서 v0.3과 UI_STRUCTURE_v01.md를 함께 제공한다. 공유 화면 URL만 있고 코드를 읽을 수 없다면 실제 소스 접근부터 확보한다.

---

기존 크루 운영 프로토타입의 기능을 보존하면서 메뉴 구조·화면·데이터 연결을 분리해 개편해.

## 기준

- 기능·상태·입력 검증·접근 범위·저장·테스트는 기능 명세서 v0.3을 유지한다.
- 메뉴·화면 배치는 UI_STRUCTURE_v01.md를 따른다. v0.3의 모든 PC 화면을 목록·상세 병렬로 만들라는 해석은 중단한다. 병렬 배치는 크루장 퀵 리뷰에 유지하고, 미션 목록과 크루원 상세는 분리한다.
- 기존 스케치와 DESIGN (2).md를 전체 앱의 고정 구조로 복제하지 않는다. 기능 명세는 새 스케치 때문에 축소하지 않는다.
- 현재 프로젝트를 먼저 읽고 수정한다. 같은 앱을 별도 프로젝트로 새로 만들어 대체하거나 기존 파일·저장 데이터를 지우지 않는다. 소스를 읽지 못했다면 수정했다고 말하지 않는다.

## 먼저 파악하고 바로 진행할 것

현재 구현된 기능 ID, 화면 구성, 데이터 타입, 공유 상태, 저장 키·버전, 이동 방식, 실행·검증 명령을 짧게 정리한다. 기존 프레임워크·라우터·스타일 도구가 있으면 유지한다.

중대한 기능 충돌이나 데이터 손실 가능성 외에는 사소한 구현 선택으로 멈추지 않는다. 기존 코드에 맞춰 파일명을 조정하되 다음 책임을 분리한다.

1. 공통 화면 틀·메뉴·시연 도구.
2. 홈·미션 목록·미션 상세·미션 개요·퀵 리뷰 페이지.
3. 상태 배지·기한·미션 기준·제출 이력·입력 폼 등 공통 표현.
4. 접근 범위를 적용한 조회·집계, 상태 전환 명령, 저장 어댑터.

## 화면 변경

- 크루원: 홈의 다음 행동 → 미션 목록 → 독립된 미션 상세. 상세 옆에 미션 목록과 빈 사이드바를 계속 붙여두지 않는다.
- 크루장: 홈·미션 목록 → 미션 개요 → 퀵 리뷰. 미션 등록은 기존 폼과 등록 후 연결을 보존한다.
- 퀵 리뷰는 상태 필터·제출 목록·상세 병렬을 유지하고, 작은 화면에서는 세로로 배치한다.
- 홈은 기존 데이터의 조회 결과다. 새 추천·성장 점수·업무 유형을 만들지 않는다.
- 알림 예시 진입·목적지는 보존하고 실제 발송 없음 표시를 유지한다.
- 예시 사용자 전환·초기화는 접을 수 있는 시연 도구로 옮긴다. 현재 예시 사용자·역할은 확인 가능해야 한다.
- 이미 구현된 이후 기능은 보존한다. 아직 구현하지 않은 관리자·성과·제안·소통 화면은 이번 작업에 새로 추가하지 않는다.

## 데이터·이동 보존

- 업무 데이터와 화면 선택 상태, 미저장 폼 입력을 분리한다. 카드·표·상세가 같은 ID의 원본을 참조한다.
- 화면별로 제출 상태와 집계를 별도로 저장하지 않는다. 미션별·대상자별 최신 상태와 버전 이력을 유지한다.
- 이동 함수에서 미저장 입력과 예시 접근 범위를 확인한다. 목록 복귀 시 유효한 필터를 유지하고 사용자·크루 변경 시 유효하지 않은 선택을 해제한다.
- 검토 처리 직후의 읽기 전용 결과, 다음 검토 버튼, 필터 변경 후 빈 상세를 기존 명세대로 보존한다.
- 저장 성공 후 상태 확정, 실패 시 입력 유지, 중복 이벤트 방지, 새로고침 유지 규칙을 보존한다.
- CSS·컴포넌트 분리를 이유로 저장 키나 schemaVersion을 바꾸지 않는다. 부득이한 변경은 호환·복구 계획을 명시한다.
- 별도 URL 라우팅 도입은 자동 필수 작업이 아니다. 기존 이동 체계로 필요한 구조를 구현할 수 있으면 활용한다.

## 완료 확인

기존 기능 테스트와 이번 이동·반응형 검사를 실행한다. 미션 등록, 최초 제출, 보완 요청, 알림 이동, 재제출, 완료, 집계 일치, 저장 실패·중복 클릭·초기화 취소·새로고침 유지를 확인한다. 기존 명세의 테스트 전제·순서를 유지한다.

390px·1280px에서 목록·상세·퀵 리뷰와 긴 제목·빈 목록을 브라우저로 확인한다. 타입 검사·빌드·프로젝트에 설정된 관련 테스트를 실행하고, 못 한 검증은 미확인으로 남긴다.

완료 보고에는 변경한 화면, 그대로 유지한 기능 ID, 데이터 저장 호환 여부, 검증 결과, 남은 문제를 적는다. 이후 묶음을 자동 구현하지 않는다.
