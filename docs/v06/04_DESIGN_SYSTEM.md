# 디자인 시스템 v0.6 초안

## 1. 목적과 적용 범위

홈은 서비스 소개·탐색, 상세는 이해·행동, 리뷰는 집중 작업이라는 차이를 유지하면서 하나의 웹사이트로 보이게 한다. 브랜드 확정안이 아닌 초기 제작 기준이다. 사용자가 제공한 Udemy 화면은 소개 문구+큰 이미지와 후속 콘텐츠 구역의 배치 참고이며 실제 로고·이미지·문구는 복제하지 않는다.

## 3. 타이포그래피·간격

- 한국어 기본 글꼴: system-ui, Malgun Gothic, sans-serif. 새 유료 폰트·외부 폰트 의존을 필수로 만들지 않는다.
- 홈 큰 제목 40px/1.2, 모바일 30px/1.3. 일반 페이지 제목 28px/1.3, 구역 제목 20px/1.4, 본문 16px/1.6, 메타 14px/1.5. 작은 시연 표기만 12px 이상.
- 제목은 600~700, 본문 400~500을 기본으로 한다. 영문 포스터의 큰 글자는 장식용이며 핵심 의미는 본문에도 제공한다.
- 간격 단위 4·8·12·16·24·32·48·64px. 섹션 48~64px, 카드 내부 24px, 작업 폼 16~24px. 모바일은 섹션 32px·내부 16~20px.
- 한국어 긴 제목을 줄바꿈하고 입력·버튼의 폭을 고정 문자 수로 제한하지 않는다.

## 4. 페이지 배치 계약

| 유형 | 최대 콘텐츠 폭 | 기본 배치 |
|---|---|---|
| 홈 | 1200px | 소개 문구+포스터 2열, 활동 소개 3열; 모바일 1열 |
| 로그인 | 600px | 제목·역할 선택·가상 계정·설명·로그인 버튼 |
| 가이드 | 960px | 상단 목차, 읽기 영역 약 760px, 세로 섹션 |
| 크루 홈·미션 목록 | 1200px | 맥락·미션 요약, 2~3열 카드/행 |
| 미션 상세·입력 | 840px | 안내·피드백·입력·이력의 세로 위계 |
| 퀵 리뷰·운영 | 1440px | 작업 비교에 적합한 폭, 필요할 때만 병렬 |

768px 미만은 모바일 배치를 기본으로 한다. 390px·1280px에서 반드시 확인하고 320px에서도 수평 넘침이 없어야 한다. 콘텐츠가 넘치면 더 일찍 세로 전환한다. 웹페이지 전체에 고정 높이·내부 스크롤을 강제하지 않는다.

## 5. 공통 헤더·메뉴·계정

헤더: 로고 → 크루 활동 → 이용 가이드 → 역할별 운영 관리 → 로그인 또는 계정. 실제 검색 기능이 없으면 검색창을 장식으로 추가하지 않는다.

드롭다운은 실제 button으로 열고 aria-expanded·aria-controls를 연결한다. 일반 내비게이션 링크 목록으로 구성하고 불필요한 ARIA menu 역할을 붙이지 않는다. Escape로 닫히며 열린 버튼에 초점을 돌린다. 이동·바깥 클릭 시 닫는다. 모바일 메뉴도 같은 경로·권한을 사용한다.

계정 영역: 이름·역할·로그아웃. 진행자용 ‘다른 계정 체험’은 별도 시연 도구에 둔다. 실제 서비스의 역할 변경 기능처럼 표현하지 않는다. 미저장 입력이 있으면 이동 확인을 거친다.

| 컴포넌트 | 사용 | 상태·주의 |
|---|---|---|
| Hero | 홈 서비스 소개 | 이미지 실패해도 제목·설명·CTA가 남음 |
| BrandPoster | 브랜드 분위기 | 가칭 표시, 정보는 별도 텍스트, 모바일 잘림 확인 |

| StatusBadge | 상태 식별 | 네 업무 상태 유지, 우수·좋아요를 추가 상태로 쓰지 않음 |

카드 안에 다시 카드·탭·작업 화면을 중첩하지 않는다. 독립 페이지가 필요한 정보는 이동으로 연결한다. 실제 입력 화면에는 설명용 ‘기능 연결 예정’ 버튼을 남기지 않는다. 이 표기는 와이어프레임에서만 사용한다.

## 7. 홈 문구·이미지 기준

가칭: CREW. 제안 제목: ‘혼자 만드는 콘텐츠에서, 함께 성장하는 크루로.’ 설명: ‘미션을 확인하고, 피드백을 나누고, 활동 기록을 이어가세요.’

첫 배너는 정적 1개로 시작한다. 자동 슬라이드·영상 배경·무한 애니메이션은 필요하지 않다. 실제 브랜드 포스터가 없으면 타이포그래피와 간단한 도형으로 구성한 콘셉트 그래픽을 사용한다. 원본 확정 후 이미지 자산만 교체할 수 있어야 한다.

포스터 안에 유일한 로그인·설명 문구를 넣지 않는다. 장식 이미지의 alt는 비우고 의미 있는 이미지는 간결한 대체 텍스트를 제공한다. 이미지 실패 시 대체 그래픽으로 레이아웃을 유지한다. 텍스트가 포함된 실제 포스터는 핵심 내용을 HTML 본문에도 제공한다.

## 8. 폼·오류·접근성

- 시연 로그인은 실제 비밀번호 입력칸이 없다. 선택 항목을 읽을 수 있는 라벨과 로그인 행동을 구분한다.
- 필수 오류는 입력 가까이에 표시하고 aria-describedby·aria-invalid를 연결한다. 오류가 색만으로 전달되지 않게 한다.
- 페이지 이동 후 문서 제목·주요 제목의 맥락이 바뀌고 키보드 사용자가 새 화면을 이해할 수 있게 한다. 포커스 이동은 사용자 동작에 맞춰 적용한다.
- 버튼·링크에 명확한 이름, 터치 목표 약 44px, focus-visible 표시를 제공한다.
- 저장 실패는 성공 토스트를 띄우지 않고 입력을 보존한다. 미저장 이탈 확인에서 취소하면 위치·입력을 유지한다.

## 9. 확장 시 규칙

새 카테고리 때문에 색·페이지 구조를 별도 복제하지 않는다. 새 기능은 동일 헤더·타이포·폼·상태 표현을 사용하되 목적에 맞는 페이지 유형을 선택한다. 장식용 빈 메뉴·빈 통계·가짜 활동 수를 넣지 않는다. 가이드·문구·업무 상태를 함께 갱신한다.
