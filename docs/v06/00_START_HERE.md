# 크루 운영 플랫폼 제작 기준 v0.6

작성일: 2026-11-11 · 사용자 승인 방향을 반영한 제작 기준 · 브랜드·색상·문구는 제안값

## 핵심 변경

기본 여정은 **공개 홈 → 로그인 → 같은 홈 → 상단 메뉴 → 핵심 기능**이다. 크루원·크루장·관리자 모두 로그인 후 P-01 홈으로 돌아온다. 공개 홈과 로그인 후 홈은 같은 페이지의 상태 차이다. 개인 업무 홈을 별도로 만들지 않는다.

로그인은 사전 등록 가상 계정으로 체험하는 시연용이다. 실제 이메일·비밀번호·개인정보를 받지 않는다. 계정 선택이 실제 인증·서버 권한 검사를 뜻하지 않는다. 업무 저장은 기존 같은 브라우저 로컬 저장을 유지한다.

## 문서별 책임

| 파일 | 책임 |
|---|---|
| 01_SERVICE_ARCHITECTURE.md | 전체 페이지 계층·공개/로그인 영역·역할별 탐색·구현 단계 |
| 02_PAGE_WIREFRAMES.md | 페이지별 구역·행동·모바일·상태·페이지 연결 |
| 03_FUNCTION_RULES.md | 기존 F·T 업무 규칙 및 신규 N·V 로그인/홈/가이드 규칙 |
| 04_DESIGN_SYSTEM.md | 색·타이포·간격·페이지 유형·컴포넌트·이미지와 상태 표현 |
| 05_SERVICE_STORYBOARD.md | 첫 방문부터 업무까지의 역할별 시나리오 |
| 06_CODING_HANDOFF.md | 기존 코드 분석→기준 확인→단계별 구현 요청 |

기능과 권한은 03, 탐색 계층은 01, 화면 구역은 02, 시각 표현은 04를 따른다. 같은 범위의 충돌은 임의로 합치지 말고 충돌 지점을 보고한다. 05의 한 장면을 전체 앱의 고정 레이아웃으로 일반화하지 않는다.

## 코딩 AI에 전달하는 방법

`CREW_BUILD_BRIEF_v06.md` 통합본 하나와 현재 소스를 제공한다. ZIP을 사용할 때는 압축을 풀어 00~06 문서만 제공한다. 통합본과 개별 문서를 중복 첨부하지 않는다.

이번 묶음은 기존 기능 원문을 포함하므로 v0.3~v0.5 문서를 추가 첨부하지 않아도 된다. 기존 문서는 보관하되 현재 기준으로 함께 사용하지 않는다. 예전 ‘승인된 화면 배치 유지’, ‘모든 화면 목록·상세 병렬’, ‘관리자 로그인 직후 운영 화면 진입’ 지시는 폐기한다.

## 보존과 변경 범위

보존: F-02~10의 업무·데이터 규칙, 버전 이력, 집계 방식, 저장 성공 후 상태 확정, 기존 저장 키·ID, 테스트의 핵심 결과.
변경: F-01 역할 진입을 시연 로그인으로 재정의, F-11 알림 연결의 로그인·사용자 확인 절차, 기존 T-04·10의 탐색 절차, 공개 홈·로그인·가이드 추가.

문서 버전 v0.6은 저장 schemaVersion이 아니다. 화면 개편을 이유로 데이터를 초기화하지 않는다. 현재 코드를 고칠지 새로 만들지는 소스 점검 후 판단하며, 새 프로젝트로 옮겨도 다른 출처의 localStorage는 자동 이전되지 않는다.

## 제공물과 검증의 구분

이번 결과는 문서와 클릭형 구조 와이어프레임이다. 실제 Claude 프로토타입 코드를 변경하거나 공개 배포한 결과가 아니다. 와이어프레임의 제출·저장 버튼은 동작 구현 범위를 뜻하지 않는다. 로그인·메뉴·페이지 전환을 살펴보는 용도다.

기존 코드에 적용한 뒤에는 빌드·기능·브라우저·반응형 검증을 별도로 수행한다. 와이어프레임의 예시 숫자는 실제 운영 성과가 아니며 기존 T 테스트 데이터와도 구분한다.

이번 검증: F-02~10 원문 보존, 문서의 F/T/N/V·P 식별자와 Markdown 구조, ZIP 무결성, 와이어프레임의 로그인·홈 복귀·권한별 탐색 등 16개 렌더링 로직 검사를 확인했다. 로직 검사는 Node와 간이 DOM 환경에서 수행했다. 실제 브라우저의 시각 배치·접근성·제품 저장 동작은 검사하지 않았다.
