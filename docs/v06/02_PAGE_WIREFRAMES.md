# 페이지 유형별 와이어프레임 v0.6

작성일: 2026-11-11. 기능 규칙은 03_FUNCTION_RULES.md, 계층은 01_SERVICE_ARCHITECTURE.md, 시각 표현은 04_DESIGN_SYSTEM.md를 따른다. 아래 배치는 텍스트만 읽는 AI도 구현할 수 있도록 작성했다.

## 1. 공통 헤더와 상태

```text
공개: [CREW/홈] [크루 활동 ▾] [이용 가이드]               [로그인]
원/장: [CREW/홈] [크루 활동 ▾] [이용 가이드]       [이름·역할 / 로그아웃]
관리: [CREW/홈] [이용 가이드] [운영 관리: 구현 후] [이름·역할 / 로그아웃]

크루 활동 펼침: 크루 홈 / 미션 / 소통(구현 후)
모바일: 로고 + 메뉴 버튼 → 같은 항목을 세로 펼침
```

크루 업무 화면에는 선택 크루명·카테고리·내부 탐색을 추가한다. 홈·로그인·가이드에는 크루 내부 메뉴를 붙이지 않는다. 관리자에게 소속 크루원 메뉴를 복사하지 않는다. 로고는 모든 역할에서 홈으로 간다.

## 2. P-01 공통 홈 — 공개 상태

```text
[전역 헤더 / 로그인]

혼자 만드는 콘텐츠에서,          ┌ 브랜드 콘셉트 포스터 ┐
함께 성장하는 크루로.            │ CREATE / LEARN       │
미션·피드백·활동을 이어가세요.    │ TOGETHER             │
[로그인하고 시작하기] [가이드]    └──────────────────────┘

함께 이어가는 활동
크루에서 시작 / 미션과 피드백 / 활동 기록

이용 과정: 로그인 → 크루 확인 → 미션 수행 → 피드백 반영
[이용 가이드 보기]
푸터: 서비스 가칭 · 시연 프로토타입
```

소개와 이미지는 정적 콘텐츠. 브랜드 포스터는 제안 시각 자산이며 실제 로고가 아니다. 강의 판매·성장 수치·리뷰·검색 기능을 추가하지 않는다. 모바일은 소개 문구·CTA→포스터→활동 섹션 순서. 핵심 설명을 이미지 안에만 넣지 않는다.

## 3. P-01 공통 홈 — 로그인 상태

```text
[같은 전역 헤더 / 이름·역할 / 로그아웃]

민지님, 활동을 이어가세요. [내 크루] [미션]
다음 행동: 보완 요청 또는 미제출 미션 요약(본인만)
[선택했던 기능으로 이동: 유효한 요청이 있을 때만]

[로그인 전과 같은 서비스 소개·포스터·활동 소개·가이드]
```

크루장은 검토 대기 요약, 관리자는 구현된 운영 관리 바로가기. 관리자 로그인도 이 홈을 거친다. 홈을 업무 대시보드로 대체하지 않는다. 할 일이 없으면 간단한 빈 안내와 크루 이동. 소개 콘텐츠를 스크롤하지 않아도 헤더·바로가기로 이동 가능.

## 4. P-12 시연 로그인

```text
[공통 헤더]
로그인
시연용 가상 계정입니다. 실제 비밀번호를 입력하지 않습니다.

[크루원] [크루장] [관리자]
시연 계정 [선택한 역할에 속한 사전 계정 ▾]
선택 계정의 역할·소속 요약
                          [취소] [시연 로그인]
```

역할 선택과 실제 로그인 행동을 구분한다. 계정의 역할·소속이 원본이고 임의 조합은 불가. 성공은 모든 역할 P-01, 취소는 이전 공개 페이지 또는 기존 계정·화면. 비로그인 보호 페이지에서 왔으면 일반 안내만 보이고 타인 이름·미션은 숨긴다. 미선택·잘못된 계정은 가까운 오류. 모바일은 같은 순서의 한 열. 회원가입·비밀번호 복구 버튼을 장식으로 만들지 않는다.

## 5. P-13 스크롤형 이용 가이드

```text
[전역 헤더]
이용 가이드
[시작] [크루 찾기] [미션] [피드백] [활동 기록] [FAQ]

01 시작: 홈 → 로그인 → 다시 홈 → 상단 메뉴
02 크루: 크루 홈과 미션 목록의 차이
03 미션: 기준·기한·텍스트/링크 제출
04 피드백: 보완 요청·수정 내용·재제출·이력
05 활동 기록: 완료 후 선택적 게시·조회수·회고
06 FAQ: 검토 완료≠게시, 시연 로그인, 미입력≠0
크루장 안내: 등록과 퀵 리뷰
관리자 절차: 관리자 로그인 후만 렌더링
```

목차는 섹션 앵커. 모바일도 가로로 잘리는 목차 대신 줄바꿈·세로 배치. 일반 문서처럼 스크롤하며 읽는다. 로그인 전 실제 작업 CTA를 누르면 보호 경로 처리. 미구현 기능은 후속 제공 안내만 표시. 장문 안내를 미션 상세에 모두 반복하지 않는다.

## 6. 내부 업무 화면 공통

P-02~10은 로그인 뒤 메뉴로 진입한다. 퀵 리뷰만 대기열+상세 병렬 구조이고 다른 화면은 자신의 목적에 맞게 독립 배치한다. 미저장 이탈·오류·권한·상태 규칙은 03을 따른다. 다음 업무 화면은 v0.5의 기능과 정보 위계를 보존한 것이다.

## 7. P-02 크루 홈 — 함께 활동하는 공간

단계: 1차, 공지 요약은 3차 · 사용자: 소속 크루원·크루장

```text
[전역 헤더]
푸드 A 크루 · 푸드 / 크루장 지훈
[크루 홈] [미션] [소통: 3차]

크루 소개
짧은 음식 콘텐츠를 제작하고 미션 피드백을 이어가는 크루

최근 미션                                     [전체 미션]
[제목 · 기한 · 역할별 상태]   [제목 · 기한 · 역할별 상태]

공지 요약                                     [소통 보기]
※ 소통 구현 후 실제 공지가 있을 때만 표시
```

- 주 행동: P-03 미션 전체 보기. 미션 요약 선택은 P-04.
- 크루원에게는 배정된 미션만, 크루장에게는 자기 크루 미션을 보여준다. 최근 생성순 최대 3개를 기본 제안으로 한다.
- 크루 소개는 사전 등록 데이터. 소개 편집·모집·가입·멤버 초대 기능은 이번 화면에 추가하지 않는다.
- 빈 상태: 크루원은 아직 배정 미션 없음. 크루장은 미션 등록 → P-06.
- 모바일: 소개와 미션 요약을 세로로 배치. 큰 이미지 배너에 첫 화면을 모두 쓰지 않는다.
- 확인: 어떤 크루인지, 누가 운영하는지, 무엇을 하러 갈지 이해되는가?

## 8. P-03 미션 목록 — 탐색과 선택

단계: 1차 · 사용자: 크루원·크루장 · F-02~06 진입

```text
[전역 헤더 / 크루 맥락 / 크루 메뉴]
미션                                      [미션 등록: 장]
[전체] [내 할 일/검토할 미션] [완료: 원]

┌ 미션 제목 ─────────┐  ┌ 미션 제목 ─────────┐
│ 목표 요약          │  │ 목표 요약          │
│ 기한 · 제출 형식   │  │ 기한 · 제출 형식   │
│ 내 상태 / 대기 건수│  │ 내 상태 / 대기 건수│
│ [미션 보기]        │  │ [미션 보기]        │
└────────────────────┘  └────────────────────┘
```

- 주 행동: 미션 보기 → P-04. 등록은 크루장만 P-06.
- 기본 정렬: 최근 생성순. 필터는 업무 상태를 새로 만들지 않고 기존 데이터에서 계산.
- 크루원: 내 상태. 크루장: 고정 대상 건수·검토 대기 수. 현재 상태를 카드 색에만 의존하지 않는다.
- 영구 오른쪽 상세를 붙이지 않는다. 카드 전체 클릭만 강제하지 않고 명시적인 제목/버튼 링크를 제공한다.
- 빈 상태: 등록 없음과 필터 결과 없음을 구분. 후자는 필터 해제 제공.
- 모바일: 한 열. 긴 제목은 여러 줄, 상태·기한·버튼은 잘리지 않게 배치.
- 확인: 여러 미션 중 하나를 선택하고 목록으로 돌아와 다른 미션을 열 수 있는가?

## 9. P-04 미션 상세 — 이해하고 행동하는 중심 페이지

단계: 1차 · 사용자: 배정 크루원·담당 크루장 · F-03·06, F-04 진입

### 크루원 기본 배치

```text
푸드 A / 미션 / 동네 맛집 첫 장면 숏폼
동네 맛집 첫 장면 숏폼
마감 · 링크 제출 · 내 상태

다음 행동: 수정 방향을 반영해 다시 제출해 주세요.
최근 피드백: 첫 3초에 핵심 장면을 먼저 보여주세요.

미션 목표와 제출 기준
① 첫 장면  ② 전달 메시지  ③ 확인할 사항

내 제출 / 수정 입력
영상 공유 링크 [                              ]
수정한 내용    [                              ]
                                               [재제출]
제출·피드백 이력
2차 제출 / 1차 제출과 당시 피드백
```

### 상태별 차이

| 상태 | 앞부분에서 보여줄 내용 | 가능한 행동 |
|---|---|---|
| 미제출 | 목표·기준·기한, 제출 안내 | 본문/링크 필수 + 설명 선택 → 최초 제출 |
| 검토 대기 | 제출 시각·버전, 검토 대기 | 제출·이력 읽기; 임의 수정 불가 |
| 보완 요청 | 최신 피드백·수정 방향 | 새 본문/링크 + 수정 내용 필수 → 재제출 |
| 완료 | 완료 결과와 해당 피드백 | 이력 읽기; 2차 이후 게시·성과 기록 선택 |

미션 기준은 항상 접근 가능하게 남긴다. 검토 완료를 실제 게시·수익 발생으로 표현하지 않는다. 링크 미션은 URL 입력, 텍스트 미션은 본문 입력이다. 파일 업로드·영상 임베드는 없다.

### 크루장 기본 배치

```text
미션 제목 / 기한 / 제출 기준
대상 3건 · 검토 대기 1 · 보완 요청 1 · 완료 1 · 미제출 0
[퀵 리뷰 열기]
대상자·상태 요약
미션 목표·기준
```

- 크루장 주 행동: P-05. 이 페이지에 피드백 작업 폼과 대기열을 전부 중첩하지 않는다.
- 오류: 필수 입력 옆 안내, 저장 실패 시 입력 유지. 접근 불가에는 내용 노출 없이 목록 복귀.
- 모바일: 한 열. 피드백·기준·입력·이력을 접을 때도 다음 행동과 최신 피드백을 숨기지 않는다.
- 확인: 크루원에게 수정할 이유와 내용이 명확한가? 크루장에게 리뷰 진입이 명확한가?

## 10. P-05 퀵 리뷰 — 미션 내부의 집중 작업

단계: 1차 · 사용자: 담당 크루장 · F-04·05·11A

```text
푸드 A / 미션 / 동네 맛집 첫 장면 숏폼 / 퀵 리뷰
[미션 상세로]                  검토 대기 1건
[검토 대기] [보완 요청] [완료] [미제출]

제출자 목록             선택한 제출물
민지 · 2차              민지 · 2차 · 제출 시각
                        [원본 링크 열기]
                        수정한 내용 / 과거 제출·피드백

                        처리 결과 (완료 / 보완 요청)
                        [첫 장면] [메시지 전달] [다음 행동]
                        설명 [                           ]
                                             [피드백 보내기]
```

- 이 화면에서만 대기열과 상세 병렬을 기본으로 사용. 전체 폭을 활용해 작은 중첩 패널을 피한다.
- 검토 대기는 제출 시각이 빠른 순. 선택 대상 변경 전 입력 확인.
- 원본 링크는 새 탭, 안전한 http/https만. 원본 접근 가능성을 보장하지 않는다.
- 보완 요청은 설명 필수, 완료는 선택. 공통 문구는 삽입 후 수정 가능. 1줄·100자 제한 없음.
- 처리 후: 대상은 대기열에서 빠지지만 상세는 방금 결과를 읽기 전용으로 유지. 다음 대상 있으면 이동, 없으면 남은 대기 없음.
- 필터 변경 후 0건: 이전 대상 상세를 비운다. 이때 과거 처리 결과를 계속 표시하지 않는다.
- 보완 요청·완료 상태의 조회에서는 새 피드백 폼을 비활성화하고 이력만 표시. 미제출은 제출물 없음.
- 모바일: 상태 필터 → 대상 선택 → 상세. 두 열을 압축하지 않는다. 현재 사람·버전이 계속 식별돼야 한다.
- 확인: 다른 미션으로 옮기지 않고 검토 흐름을 이어갈 수 있는가? 수정본과 원본의 피드백이 구분되는가?

## 11. P-06 미션 등록 — 입력 중심 페이지

단계: 1차 · 사용자: 크루장 · F-02

```text
푸드 A / 미션 / 새 미션
미션 등록
크루: 푸드 A (고정)
제목* [                           ]
목표·제출 기준* [                 ]
제출 형식* (텍스트 / 링크)       마감 일시* [          ]
대상자* [민지] [준호] [하늘]
                                      [취소] [등록]
```

자기 크루 구성원 1명 이상. 저장 후 해당 미션 P-05로 이동하고 고정 대상 전체가 미제출로 집계된다. 초안·반복·예약·생성 후 편집·삭제는 없다. 취소는 P-03이며 입력이 있으면 확인한다. 모바일도 같은 필드 순서로 한 열.

## 12. P-07 게시·성과 기록 — 결과물의 후속 입력

단계: 2차 · 사용자: 검토 완료된 본인 결과물의 크루원 · F-07

```text
크루 / 미션 제목 / 게시·성과
완료 결과물 · 게시 기록은 선택

게시 정보
플랫폼* [      ] 실제 게시 URL* [                  ]
게시일* [      ]                         [게시 정보 저장]

성과·회고
확인일 [       ] 조회수 [       ] 회고 [            ]
입력 출처: 수동                          [성과 기록 저장]
과거 확인일별 기록
```

검토용 링크와 실제 게시 URL을 구분. 게시만 저장 가능. 조회수·회고 중 하나라도 입력하면 확인일 필수. null과 0을 구별. 같은 확인일은 수정, 다른 날짜는 관찰 추가. 게시 정보 없이 빈 성과 기록만 만들지 않는다. 완료 상태는 바뀌지 않는다. 미션 상세 복귀 제공. 모바일은 정보 구역 순서대로 세로 배치.

## 13. P-08 크루 소통 — 공개 소통과 개인 피드백 구분

단계: 3차 · 사용자: 같은 크루의 크루장·크루원 · F-10

```text
푸드 A / 소통
[공지·질문 목록]                             [글 작성]
글 구분 · 제목 · 작성자 · 시각
글 구분 · 제목 · 작성자 · 시각

글 선택 후: 목록 대신 글 상세
제목 / 본문 / 관련 미션(선택) / 댓글 / 댓글 입력
                                            [목록으로]
```

공지·질문 등 역할별 작성 범위는 03의 F-10을 따른다. 글 작성은 제목·본문·구분, 관련 미션은 선택. 관련 미션이 비대상자용이면 미션 내용은 열지 못한다. 개인 보완 요청을 공개 글로 자동 전환하지 않는다. 글이 없으면 빈 안내와 역할별 작성 행동. 모바일은 목록→상세 전환, 댓글은 세로.

## 14. P-09 운영 관리 — 여러 크루를 한 화면에서

단계: 2차 · 사용자: 담당 관리자 · F-08

```text
CREW / 운영 관리
담당 크루 현황
[크루: 전체] [기간: 전체] [미션: 전체]
대상 5건 = 검토 대기 1 + 보완 요청 0 + 완료 1 + 미제출 3

크루       카테고리    대상    대기    보완    완료    미제출
푸드 A     푸드        3       0       0       1       2
뷰티 B     뷰티        2       1       0       0       1

푸드 A 선택 시 구성원
이름          선택 범위의 대상·상태                [개인 보기]
```

모든 수치는 같은 필터가 적용된 대상자-미션 조합 기준. 미션 마감일로 기간 필터, 한국 시간. 같은 사람이 여러 미션에 있어도 합계를 사람 수로 표현하지 않는다. 재제출 버전을 별도 대상 건수로 세지 않는다.

크루 선택 시 구성원 목록 표시. 개인 보기 → P-10. 기간·미션 필터가 바뀌면 선택 개인·미션의 유효성을 검사. 조회 범위가 0이면 빈 상태와 필터 해제. 모바일에서는 크루별 행을 라벨 있는 요약으로 재배치하거나 필요한 표에만 스크롤을 적용한다.

## 15. P-10 크리에이터 상세 — 동일 기록을 역할에 맞게 조회

단계: 2차 · 사용자: 담당 관리자 · F-08·09

```text
운영 관리 / 푸드 A / 민지
민지 · 소속 크루
[활동] [콘텐츠 성과] [제안 이력]

활동: 미션 / 최신 상태 / 버전·시각 / 피드백 이력
콘텐츠 성과: 게시 URL / 수동 확인일 / 조회수·회고
제안 이력: 제안일 / 광고·커머스 / 브랜드·상품 / 진행 상태
                                  [제안 등록: 제안 탭]
```

탭은 같은 개인 ID를 유지. 성과 미집계와 0 구분, 확인일 표시. 활동에서 개인 제출·피드백 읽기 전용 확인, 관리자 대행 피드백은 없다.

제안 등록·상세 폼: 제안일·담당자·구분·브랜드/상품·내용·진행 상태 필수, 내부 메모 선택. 상태 수정 이력 보존, 삭제 없음. 저장은 외부 메시지 발송이 아니다. 개인 상세의 하위 입력 상태로 열고 목록 복귀와 미저장 확인 제공.

모바일은 탭 줄바꿈과 세로 기록. 필드가 많다는 이유로 내부 메모를 다른 역할의 공통 프로필에 재사용하지 않는다.


## 16. P-11 진행자 시연 도구

로그인 후 접을 수 있는 보조 영역. ‘다른 계정 체험’은 P-12로 이동하고 기존 세션을 선택 완료 전까지 유지한다. 초기화는 확인 후 가상 업무 데이터만 복원. 알림 예시는 현재 역할 범위만 표시한다.

같은 대상 계정이면 알림에서 해당 P-04 버전으로 이동. 다른 계정이면 로그인 안내→P-12→P-01→선택했던 피드백 보기. 자동 계정 전환은 없다. 카카오·이메일 실제 발송 표시 없음.

## 17. 연결과 검토

공개 진입: P-01→P-12→P-01→헤더의 P-02/P-03/P-09. 가이드: P-01→P-13→P-12→P-01. 기존 기능: 등록 P-03→06→05, 제출·재제출 P-04, 리뷰 P-05, 성과 P-04→07, 운영 P-09→10, 소통 P-02→08.

각 역할에서 ‘홈으로 돌아왔는가’, ‘메뉴에서 원하는 기능을 찾는가’, ‘크루·미션·작업의 현재 위치가 명확한가’, ‘가이드로 방법을 찾고 업무로 돌아오는가’를 확인한다. 실행 검수는 03의 V와 기존 T를 따른다.

클릭형 와이어프레임은 가상 계정 로그인·로그아웃·메뉴·페이지·가이드 탐색을 보여준다. 업무 입력·저장·실발송은 구현하지 않는다. 역할별 대표 3계정만 보여주는 와이어프레임과 실제 기능 검증용 전체 예시 계정 목록은 구분한다. 화면 검토용 예시 데이터는 원본 T 데이터와 별개다.
