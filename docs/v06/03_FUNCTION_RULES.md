# 기능·데이터·검증 규칙 v0.6

작성일: 2026-11-11. F-02~10의 업무 규칙을 보존하고 F-01·11의 진입 및 알림 절차를 갱신했다. 전체 구조는 01, 화면은 02, 시각 기준은 04를 따른다. 신규 홈·로그인·가이드 규칙은 아래 N-01~07, 검증은 V-01~12다.

## 목적과 범위

크루장은 미션과 제출물을 관리·피드백하고, 크루원은 다음 행동을 이해하며, 관리자는 동일 기록을 여러 크루와 개인 단위로 확인한다. 검증 대상은 핵심 업무와 사용성이다. 리텐션·교육 효과·수익성을 이 프로토타입으로 입증하지 않는다. 실제 운영 베타·외주 계약서와 구분한다.

실제 동작은 같은 브라우저의 가상 데이터 입력·저장·조회·상태 변경이다. 역할 전환과 외부 알림은 시뮬레이션이다. API·실발송·영상 업로드·모집·계약·평가·정산·캠페인 전체 운영은 보류한다.

[제작 가정]은 테스트를 위해 임시 적용하는 규칙이며 회사의 확정 운영 정책이 아니다. 현재 저장 데이터·기능이 이미 구현돼 있으면 소스를 읽고 호환성을 유지한다.

## 기존 화면 ID와 새 페이지의 연결

기능 본문의 SC 번호는 기존 기능 추적용 별칭이다. 이전 화면 배치나 영구 병렬 레이아웃을 뜻하지 않는다.

| 기존 별칭 | v0.6에서 유지하는 업무 화면 연결 |
|---|---|
| SC-01 미션 목록·등록 | P-03 목록, P-06 등록, 크루장의 P-04 미션 상세 |
| SC-02 퀵 리뷰 | P-05: 선택 미션 상세에 속한 작업 화면 |
| SC-03 크루원 내 미션 | P-03 목록에서 P-04 독립 상세로 이동 |
| SC-04 게시·성과 | P-04 완료 결과물에서 P-07 |
| SC-05 소통 | 크루 공간 P-08 |
| SC-06 관리자 전체 크루 | 운영 관리 P-09 |
| SC-07 개인 상세 | P-09에서 P-10 |
| SC-08 알림 미리보기 | P-11에서 연결된 P-04 또는 해당 미션 |

P-01은 공개 소개와 로그인 사용자 요약을 함께 제공하는 공통 홈이다. P-12 시연 로그인·P-13 가이드를 추가한다. 업무 데이터는 유지하고 시연 세션과 정적 소개·가이드를 분리한다. 크루 홈 P-02는 기존 데이터 조회 화면이다.

## 역할과 제작 가정

### 역할별 접근 범위

크루원: 배정된 미션, 본인 제출·피드백·게시·성과 기록. 같은 크루의 공지·질문·댓글.

크루장: 자기 크루의 미션 생성, 대상자 지정, 제출물 검토·피드백, 활동 현황, 크루 소통. 회사 내부 제안 메모는 표시하지 않는다.

관리자: 담당 크루 여러 개의 현황과 구성원·개인 활동·성과, 광고·커머스 제안 이력. 첫 버전에서는 공통 관리자 화면 하나를 사용한다.

원본의 최고 관리자·매니저 구분은 후속 권한 설계에 보존한다. 이번에는 역할 부여·크루 이동 승인·설정 화면을 만들지 않는다. 예시 사용자의 소속·담당 크루는 사전 등록한다.

P-12에서 시연 계정을 선택하면 계정에 지정된 역할·소속으로 접속한다. 실제 인증·서버 권한 검사가 아니다. 상단 임의 역할 전환을 기본 진입으로 사용하지 않는다. 실제 인물의 연락처·계약·수익 자료를 입력하지 않는다.

### 첫 제작에서 적용할 가정

A-01: 진행자가 한 브라우저 탭에서 예시 사용자를 전환하는 테스트. 저장은 브라우저 로컬 저장소로 하며 다른 기기·브라우저·동시 탭과 동기화하지 않는다.

A-02: 미션별 제출 형식은 텍스트 또는 링크 중 하나. 대표 시나리오는 영상 공유 링크다. 기획안 승인 후 영상 승인으로 이어지는 두 단계 검토는 제외한다.

A-03: 미션당 대상자별 결과물 1개와 수정 버전 여러 개. 주간 콘텐츠 3개 등 복수 결과물 목표는 제외한다.

A-04: 미션 생성 시 대상자를 고정한다. 이후 합류자는 기존 미션의 미제출자로 자동 추가하지 않는다. 첫 버전은 생성 후 대상·기한·형식 수정과 미션 삭제를 지원하지 않는다.

A-05: 검토 완료 후 게시 기록을 선택적으로 입력한다. 텍스트·링크 미션 모두 게시 기록 없이 완료 상태를 유지한다. 이미 게시된 콘텐츠의 사후 검토와 완료 후 재개방은 후속 확인한다.

A-06: 마감 이후에도 제출·재제출을 허용하고 ‘기한 후 제출’을 표시한다. 별도 재제출 마감, 자동 종료, 벌점은 적용하지 않는다.

A-07: 과제·피드백은 본인·담당 크루장·담당 관리자에게만 표시한다. 게시글·댓글은 같은 크루에 공개한다. 동료의 개인 성장 지표 공개는 이번 범위에서 제외한다.

원본의 상시 영입·정원 15명·성인 참여·4주 온보딩 등 정책은 원본의 확정 표기를 보존한다. 이번 제작은 사전 구성한 크루를 사용하므로 모집·연령 확인·온보딩 자동화를 만들지 않는다.



## 기능 명세

### F-01 시연 로그인·역할·저장·초기화

사용자·화면: 방문자는 P-12에서 역할 구분과 해당 역할의 사전 등록 계정을 선택한다. 실제 사용자 생성·비밀번호 입력 없이 시연 로그인한다. 대표 계정 외에도 기존 F/T 검증에 필요한 민지·준호·하늘·소라·유나·지훈·유진·서연을 제공한다. 역할은 선택 계정의 데이터에서 결정한다.

동작: 시연 로그인 성공 후 역할에 관계없이 P-01 홈. 기존 미션·제출·피드백·성과·제안 데이터는 같은 업무 저장소를 참조한다. 업무 데이터는 새로고침 후 유지한다. 세션은 메모리에만 두고 새로고침 시 비로그인으로 시작한다. 다시 로그인하면 저장된 업무 기록을 조회한다.

로그아웃: 미저장 입력 확인 후 세션·선택 개인·임시 입력을 해제하고 공개 홈으로 이동한다. 업무 기록은 삭제하지 않는다. 다른 계정 체험은 P-12를 경유하고 선택 완료 후 홈으로 돌아온다. 취소하면 기존 계정과 위치를 유지한다.

저장·초기화: 다음 업무 상태 전체를 검증·저장한 뒤 화면 상태를 확정한다. 실패 시 성공 메시지·상태 변경 없이 입력을 유지한다. 초기화는 P-11에서 확인 후 이 앱의 가상 업무 데이터만 복원한다. 다른 앱의 저장소를 지우지 않는다. 확인 취소 시 변화가 없다. 호환되지 않는 저장 버전을 자동 삭제하지 않는다.

완료 기준: 각 역할이 로그인 후 홈에서 해당 기능에 접근한다. 같은 기록이 크루원·크루장·관리자에게 접근 범위에 맞게 표시된다. 새로고침으로 로그인이 풀려도 재로그인 후 기록·버전·피드백은 보존된다.

### F-02 미션 등록·대상 지정

사용자·화면: 크루장 / SC-01. 필수: 제목, 목표·제출 기준, 제출 형식(텍스트/링크), 마감 일시, 대상자 1명 이상. 크루는 본인 소속으로 고정한다.

동작: 자기 크루의 사전 등록 구성원 중 대상자를 고른다. 등록 즉시 대상자의 내 미션에 표시한다. 대상자는 미션 생성 시점 명단으로 저장한다. 제목·기준의 공백 입력, 대상자 없음, 잘못된 날짜는 등록을 막는다.

범위: 초안·예약 공개·반복 미션·생성 후 수정·삭제·다중 첨부는 제외. 등록된 미션이 없으면 빈 화면과 ‘미션 등록’을 제공한다.

완료 기준: 새 미션 등록 후 대상자에게만 표시되고, 대상자 전체가 미제출로 집계된다.

### F-03 최초 제출

사용자·화면: 크루원 / SC-03. 필수: 미션이 지정한 텍스트 본문 또는 영상 공유 링크. 설명은 선택.

동작: 미션 기준·마감과 현재 상태를 먼저 보여준다. 링크는 http/https 형식만 허용하며 서버 접근 가능 여부까지 확인했다고 표시하지 않는다. 저장 시 1차 버전·제출자·시각을 기록하고 검토 대기로 바꾼다.

예외: 필수값 누락·잘못된 URL은 해당 입력 옆에 오류를 표시한다. 저장 중 버튼을 비활성화해 연속 클릭에 따른 중복 버전을 방지한다. 마감 이후는 제출을 허용하되 기한 후 표시를 남긴다.

완료 기준: 제출한 텍스트·링크·설명을 크루장 리뷰에서 확인하고, 미제출 수가 1 줄며 검토 대기 수가 1 증가한다.

### F-04 퀵 리뷰·원본 확인

사용자·화면: 크루장 / SC-02. 상태 필터: 검토 대기, 보완 요청, 완료, 미제출. 기본은 검토 대기다.

동작: 제출자 목록과 선택한 사람의 최신 제출·버전·시각·설명·이전 피드백을 함께 보여준다. 검토 대기는 제출 시각이 빠른 순서로 정렬한다. 텍스트는 화면에서 읽고 영상 링크는 새 탭으로 연다.

처리 후: 방금 처리한 사람은 검토 대기 목록에서 제외하고, 상세에는 처리 결과를 읽기 전용으로 유지한다. 다음 대상이 있으면 ‘다음 검토 대기’를 활성화한다. 없으면 버튼을 비활성화하고 ‘남은 검토 대기 없음’을 표시한다. 필터·미션을 변경한 결과가 비어 있으면 상세도 빈 상태로 바꾼다.

완료 기준: 목록 페이지로 되돌아가지 않고 다음 제출물을 검토한다. 처리 직후의 읽기 전용 결과와, 조건 변경 후의 빈 목록을 구별한다. 이전 대상에 새 피드백을 중복 입력할 수 없고 원본 영상 임베드·자동 재생은 요구하지 않는다.

### F-05 피드백·처리 결과

사용자·화면: 크루장 / SC-02. 입력: 완료 또는 보완 요청, 공통 문구 선택(선택), 자유 설명.

규칙: 보완 요청은 수정 방향을 필수로 받는다. 완료 설명은 선택이다. 고정 문구 3개(첫 장면·메시지 전달·다음 행동)를 자유 설명란에 삽입하고 수정할 수 있게 한다. 문구 관리 화면은 없고 1줄·100자 제한도 없다. ‘우수’는 업무 상태가 아니다.

저장: 피드백은 검토한 제출 버전·작성자·시각·처리 결과에 연결한다. 최신 버전이 검토 대기일 때만 처리한다. 결과와 F-11A 알림 예시를 함께 저장한다. 관리자 화면 제작 전에도 같은 상태 집계 계산을 검증할 수 있어야 한다.

예외·완료 기준: 빈 보완 설명은 저장되지 않는다. 이미 처리한 버전을 다시 클릭해 피드백이 중복되지 않는다. 과거 피드백의 수정·삭제는 이번 범위에서 제외한다.

### F-06 수정·재제출

사용자·화면: 크루원 / SC-03. 조건: 본인 제출물의 최신 상태가 보완 요청. 입력: 새 텍스트/링크와 수정한 내용(필수).

동작: 이전 제출과 피드백을 먼저 보여준다. 수정본 저장 시 같은 미션·크루원의 결과물 아래 버전 번호를 증가시키고 검토 대기로 바꾼다. 과거 제출 내용과 피드백은 덮어쓰지 않는다.

예외: 검토 대기 중 임의 수정, 완료 후 재제출, 버전 삭제는 제외한다. 변경 내용이 비어 있으면 제출을 막는다. 링크가 같아도 외부 파일 수정 가능성을 고려해 형식만으로 재제출을 막지 않는다.

완료 기준: 크루장이 1차 피드백과 2차 수정 내용을 구별하고, 집계는 결과물 1건으로 유지된다.

### F-07 게시·성과·회고 기록

사용자·화면: 크루원 / SC-04. 조건: 결과물 검토 완료. 게시·성과 기록은 선택 작업이며 입력하지 않아도 완료 상태를 유지한다. 게시 기록을 저장할 때만 플랫폼, 게시 URL, 게시일을 필수로 받으며 검토용 공유 링크와 구분한다.

성과 입력: 성과 확인일, 조회수, 회고. 조회수는 비워두거나 0 이상의 정수로 입력한다. 성과 수치 또는 회고를 남기면 확인일이 필수이고 게시일보다 앞설 수 없다. 모든 화면의 날짜·시간 표시는 한국 시간 기준이다.

동작: 결과물당 실제 게시물 1개. 게시 정보만 먼저 저장할 수 있다. 조회수·회고가 모두 비어 있으면 성과 관찰 기록을 만들지 않는다. 값이 하나라도 있으면 확인일을 필수로 받고, 같은 게시물·같은 확인일은 수정, 다른 확인일은 새 관찰 기록으로 추가한다. 빈 조회수는 null로 저장하고 0으로 변환하지 않는다.

완료 기준: 미게시·게시했으나 미집계·조회수 0을 구별한다. 관리자 개인 성과에 게시 URL·확인일·수치·회고가 연결된다. 계정 API·자동 수집·매출 추정은 하지 않는다.

### F-08 전체 크루·개인 활동 조회

사용자·화면: 관리자 / SC-06·07. 기본 필터: 담당 크루 전체·전체 기간·전체 미션. 선택 항목: 크루 전체/개별, 미션 마감일 기준 기간, 미션 전체/개별. 기간은 한국 시간 기준 시작일 00:00 이상부터 종료일 다음 날 00:00 미만까지 포함한다.

집계: 분모는 선택된 미션들의 ‘대상자-미션’ 조합 수다. 각 조합의 최신 상태만 센다. 재제출 버전 수를 제출 인원으로 더하지 않는다. 전체 미션 조회는 단위를 ‘명’ 대신 ‘건’으로 표시한다.

이동: 전체 크루 → 크루 구성원 → 개인 상세의 활동·콘텐츠 성과·제안 이력. 활동에는 미션, 상태, 제출 버전·시각, 피드백 이력을 표시한다. 성과는 게시물별 수동 입력 기록을 보여준다.

완료 기준: 네 상태의 합계가 대상 건수와 같고 개인 기록과 일치한다. 제출·피드백 상태는 즉시 갱신하되 콘텐츠 지표는 마지막 수동 확인일을 표시한다. 자동 성장 점수·순위·수익 차트는 제외한다.

### F-09 광고·커머스 제안 이력

사용자·화면: 관리자 / SC-07 제안 탭. 필수: 크리에이터, 제안일, 담당자, 구분(광고/커머스), 브랜드·상품명, 제안 내용, 진행 상태. 내부 메모는 선택.

상태 가정: 제안 준비, 제안 전달, 협의 중, 진행 확정, 보류, 종료. 어떤 상태로든 수동 변경할 수 있고 변경 전후 상태·담당자·시각을 기록한다. 같은 값의 재저장은 상태 변경 이력을 추가하지 않는다. ‘제안 전달’은 외부에서 전달한 사실을 사람이 기록하는 상태다.

동작: 개인별 제안 목록과 상세·내부 메모를 보여준다. 크루원·크루장 화면에는 내부 메모를 노출하지 않는다. 새 제안 등록과 상태 수정은 가능하되 삭제는 제외한다.

완료 기준: 같은 사람에게 여러 제안을 기록하고 최근 이력을 찾을 수 있다. 저장을 메시지 발송으로 표현하지 않는다. 후보 추천·수락/거절·광고주 검수·계약·정산 흐름은 구현하지 않는다.

### F-10 크루 소통·관련 미션

사용자·화면: 크루장·크루원 / SC-05. 입력: 글 구분, 제목·본문, 관련 미션(선택). 댓글은 본문 필수.

규칙: 크루장은 공지·질문, 크루원은 질문을 작성한다. 공지는 목록 상단에서 먼저 보여주고 각 구분 안에서는 최신순으로 정렬한다. 댓글은 작성순으로 표시한다. 작성자·작성 시각을 기록한다.

연결: 작성자는 자기에게 보이는 같은 크루 미션만 연결한다. 게시글·댓글은 크루 전체에 공개하되, 미션 대상자 또는 담당 크루장만 연결 미션을 연다. 비대상자는 제목·내용 대신 ‘대상자 전용 미션’ 표시와 비활성 버튼을 본다. 화면 ID를 직접 지정해도 예시 접근 범위를 확인한다. 제출·피드백은 글에 자동 노출하지 않는다.

완료 기준: 같은 크루의 다른 예시 사용자로 전환해 글·댓글을 확인한다. 다른 크루 글은 섞이지 않는다. 실시간 채팅·첨부파일·검색·좋아요·게시글 수정/삭제는 제외한다.

### F-11 알림 시뮬레이션

P-11은 로그인한 진행자의 보조 시연 공간이다. F-11A 피드백 도착·연결은 1차, F-11B 마감 후 미제출 안내는 3차. 실제 발송 기능은 없다. 보조 도구에서도 크루원은 본인, 크루장은 자기 크루, 관리자는 담당 크루 범위의 예시만 본다.

F-11A: F-05 저장 시 대상자·미션·결과물·피드백 ID와 연결된 알림 예시 1개 생성. 같은 피드백 이벤트로 중복 생성하지 않는다. 대상 계정으로 이미 로그인했다면 관련 P-04 버전으로 이동한다. 비로그인이거나 다른 계정이면 대상 계정 로그인 안내를 거쳐 P-12로 이동한다. 임의로 세션을 바꾸지 않는다.

로그인 완료 후 항상 P-01에 도착한다. 대상과 권한이 일치하면 홈에 ‘선택했던 피드백 보기’를 표시하고 클릭 시 연결된 P-04의 피드백 버전을 강조한다. 과거 알림을 열어도 최신 상태를 함께 표시하고 수정 가능 여부는 최신 상태로 판단한다. 다른 계정으로 로그인하면 해당 피드백 링크를 표시하지 않는다.

F-11B: 크루장은 자기 크루, 관리자는 담당 크루에서 미리보기 버튼을 사용한다. 클릭 시점에 마감이 지났고 최초 제출이 없는 대상자만 계산한다. 보완 요청자는 제외한다. 대상이 없으면 0명을 표시한다. 발송 성공 문구는 없다.

카카오·이메일 실발송, 자동 예약·재시도·주기적 독촉은 없다. 실제 제품 알림의 보안·외부 딥링크 인증을 구현한 것으로 표현하지 않는다.

## 공통 상태·데이터 규칙

### 상태 변경과 예외

미제출 → 검토 대기: 대상 크루원이 최초 제출. 검토 대기 → 보완 요청/완료: 담당 크루장이 최신 버전을 처리. 보완 요청 → 검토 대기: 크루원이 수정본을 제출.

미제출은 대상자에게 결과물이 없는 상태다. 작성 중 내용은 제출로 세지 않는다. 자동 임시저장은 제외한다. 입력 변경 후 앱 내 메뉴·대상자·미션·예시 사용자·초기화 이동 시 ‘저장하지 않고 이동할까요?’를 확인한다. 취소하면 입력을 유지하고, 이동을 승인하면 버린다. 브라우저 종료·새로고침 경고는 지원 범위에서 처리하며 입력 보존을 보장하지 않는다.

완료는 내부 검토 결과다. 실제 게시·성과 입력·제안 진행 상태와 독립적으로 저장한다. 오류로 저장하지 못한 경우 네 상태와 집계를 바꾸지 않는다.

링크 접근 불가: 크루장이 보완 요청과 ‘링크 접근 권한을 확인해 주세요’ 설명을 남긴다. 별도 오류 상태는 추가하지 않는다. 링크 형식 검사만으로 원본이 존재하거나 누구나 열 수 있다고 판단하지 않는다.

### 최소 데이터 연결

사용자·크루·소속·관리자 담당: 예시 사용자 ID, 역할, 크루 ID, 담당 크루 ID 목록. 별도 관리 화면 없이 초기 데이터로 제공.

미션·대상자: 미션 ID, 크루 ID, 제목, 기준, 제출 형식, 마감, 생성자·시각, 고정 대상 사용자 ID 목록.

결과물·제출 버전: 미션 ID와 크루원 ID로 결과물 1개. 버전마다 본문/공유 URL, 설명·수정 내용, 제출 시각. 최신 상태와 버전 ID 유지.

피드백: 결과물·제출 버전 ID, 처리 결과, 설명, 작성자·시각. 댓글처럼 버전과 무관하게 흩어지지 않게 저장.

게시물·성과 관찰: 완료 결과물 ID, 플랫폼·게시 URL·게시일. 관찰에는 게시물 ID·확인일·조회수(null 허용)·회고·수정 시각. 수치 출처는 ‘수동’으로 표시.

제안 이력: 크리에이터 ID, 제안 ID, 제안일·담당자·유형·브랜드/상품·내용·상태·내부 메모·변경 이력.

소통·댓글: 크루 ID, 글 ID, 작성자·시각·구분·내용·관련 미션 ID. 댓글은 부모 글 ID와 연결.

알림 예시: 이벤트 ID, 대상 사용자 ID, 종류, 관련 미션·결과물·피드백 ID, 생성 시각. 외부 발송 상태는 만들지 않는다.

같은 기록을 역할마다 별도 복사해 저장하지 않는다. 집계는 원본 데이터에서 계산하고, 예시 총계를 화면에 고정 숫자로 작성하지 않는다.

## 검증 시나리오와 완료 기준

### 재현 가능한 예시 데이터

푸드 A: 크루장 지훈, 크루원 민지·준호·하늘. 뷰티 B: 크루장 유진, 크루원 소라·유나. 관리자 서연은 두 크루 담당. 모두 가상 인물이며 실제 계정·수익을 사용하지 않는다.

크루별 대표 미션 1개. 초기 푸드 A는 민지 미제출·준호 완료·하늘 미제출, 뷰티 B는 소라 검토 대기·유나 미제출. 총 대상 5건 = 검토 대기 1 + 보완 요청 0 + 완료 1 + 미제출 3.

예시 날짜·제출 이력은 최초 실행 또는 사용자가 명시적으로 초기화할 때만 생성해 함께 저장한다. 대표 미션 기한은 생성 기준 시각보다 이전으로 설정하고 ‘시연용 기한’이라고 표시한다. 새로고침 때 날짜를 재생성하지 않는다. 실제 제출 시각·마감 비교는 당시 현재 시각을 사용한다. 새 미션은 입력한 기한을 적용한다.

### 핵심 경로 인수 조건

- T-01: 별도 초기 상태에서 크루장이 특정 대상자에게 새 미션을 등록하면 대상자에게만 보이고, 대상자 모두 미제출로 계산된다. 확인 후 예시 데이터를 초기화하고 T-02~08을 진행한다.

- T-02: 민지 최초 제출 후 전체 집계는 검토 대기 2·보완 요청 0·완료 1·미제출 2. 민지 제출 버전은 1개다.

- T-03: 민지에게 보완 요청 후 전체 집계는 검토 대기 1·보완 요청 1·완료 1·미제출 2. 빈 수정 방향은 저장되지 않는다.

- T-04: 알림 예시를 열고, 계정이 다르면 민지로 시연 로그인한 뒤 홈의 ‘선택했던 피드백 보기’를 눌러 해당 제출물로 이동한다. 수정 내용과 새 링크로 재제출하면 검토 대기 2·보완 요청 0·완료 1·미제출 2. 과거 피드백이 남는다.

- T-05: 크루장이 수정본을 완료하면 검토 대기 1·보완 요청 0·완료 2·미제출 2. 결과물 수는 증가하지 않고 제출 버전만 2개다.

- T-06: 민지가 게시 기록과 조회수 0을 저장하면 관리자 성과에 ‘0’으로 보인다. 미입력은 ‘미집계’로 구분되고 확인일도 표시된다.

- T-07: 관리자가 제안을 등록·수정하면 민지의 제안 이력에 남고, 크루장·크루원 메뉴에는 내부 메모가 보이지 않는다.

- T-08: 공지·질문·댓글을 등록하고 같은 크루 역할로 확인한다. 관련 미션 이동과 다른 크루 글 제외가 동작한다.

- T-09: 일부 구성원만 대상인 미션을 공지에 연결하면 비대상 크루원은 게시글만 읽고 연결 미션의 내용·제출물은 열 수 없다.

- T-10: 새로고침 후 비로그인 홈에서 다시 로그인하거나 다른 계정으로 시연 로그인해도 저장된 예시 날짜·버전·피드백이 바뀌지 않는다. 다른 예시 크루 사용자를 고르면 데이터 범위도 바뀐다.

- T-11: 마지막 검토 대상을 처리하면 읽기 전용 결과와 ‘남은 검토 대기 없음’이 보인다. 이후 빈 필터로 이동하면 상세가 비워진다.

- T-12: 게시 정보만 저장하면 빈 성과 관찰 기록은 생기지 않는다. 조회수 0을 입력하면 관찰 기록이 생기고, 동일일 수정·다른 날짜 추가가 구분된다.

T-02~06의 기대 집계는 초기화 후 대표 미션 두 개만 있는 상태를 기준으로 한다. T-01의 추가 미션은 남기지 않는다. 1차에서는 공통 집계 함수 결과를 검증하고, 관리자 화면 구현 후 같은 수치가 보이는지 재확인한다.

### 공통 확인

잘못된 URL, 누락된 필수값, 음수·소수 조회수, 게시일보다 이른 확인일을 저장하지 않는다. URL은 http/https만 허용한다.

연속 클릭으로 제출·피드백이 중복되지 않는다. 빈 목록·저장 실패·초기화 취소를 확인한다.

역할 전환과 새로고침 후 상태·버전·관찰 기록·메모가 일치한다. 초기화하면 원래 예시로 돌아온다.

PC와 모바일 폭에서 핵심 입력·버튼이 잘리지 않고, 상태는 색만으로 구분하지 않는다. 키보드로 입력과 주요 버튼을 사용할 수 있다.

사용자 관찰: 크루장은 검토 대상을 찾고 수정본을 구별하는가, 크루원은 수정할 내용을 자신의 말로 설명하는가, 관리자는 필요한 개인 이력을 찾는가. 성공 여부·막힌 지점·진행자 도움·소요 시간을 기록한다. 효과 수치는 테스트 전 확정하지 않는다.



## 후속 확인과 실제 운영 전환

Q-01 검토 대상·순서: 기획안과 제작물 중 무엇이 핵심이며, 두 단계 승인 또는 게시 후 피드백이 필요한가? 첫 프로토타입은 단일 검토 흐름으로 진행.

Q-02 운영 규칙: 미션당 복수 결과물, 재제출 기한, 완료 후 수정, 중간 합류자의 대상 포함 규칙이 필요한가? 테스트에서 실제 사례를 수집.

Q-03 공개 범위·담당자: 동료 성장 지표 공개, 관리자 대행 피드백, 복수 담당 매니저의 수정 권한을 확인. 첫 버전의 메뉴 분리는 보안 검증으로 간주하지 않음.

Q-04 주변 업무: 출석·온라인 모임 링크·자료 관리 중 첫 실제 운영에 필수인 항목을 확인. 우선 외부 도구·공지로 처리 가능 여부 판단.

Q-05 운영 환경: 각자 기기에서 실제 데이터를 쓰기 전 공용 저장소, 로그인·서버 권한, 백업·오류 대응, 개인정보 처리 범위 등을 별도 구현·검증. 실제 카카오 발송과 API는 연동 조건·비용·실패 대응 확인 후 결정.

Q-06 사업 정책: 계약·수익 배분·평가·제재는 원본 정책 자료로 유지. 이번 프로토타입의 피드백 횟수·응답 시간만으로 보상이나 평가를 자동 결정하지 않음.

상기 질문은 첫 제작을 멈추기 위한 조건이 아니다. 제작 가정으로 테스트를 진행하고, 확인 결과가 바뀌면 영향받는 기능 ID와 상태·데이터·화면을 함께 수정한다.

## 제작 순서와 완료 구분

실제 코드 적용은 소스 확인 후 진행한다. 먼저 P-01·12·13과 신규 N 규칙을 연결하고, 기존 F-01~06·F-08 계산·F-11A를 P-02~06·11과 연결한다. F-02 등록·F-11A 이동을 화면 개편 중 누락하지 않는다.

1차 기능의 검사: T-01~05, T-10·11, 저장 실패·중복 처리와 공통 검증. 관리자 화면이 없어도 집계 함수를 확인한다.
2차 추가 범위: F-07~09. 관리자 결과와 T-06·07·12 확인.
3차 추가 범위: F-10·F-11B. T-08·09와 통합 검증.
이미 구현된 이후 기능은 유지하며 새 구조에 연결한다. 아직 없는 이후 기능은 자동 구현하지 않는다.

전체 구조 완료는 신규 V-01~12, 기존 기능 보존은 이 문서의 T·공통 검증으로 판단한다. 화면이 예쁘게 바뀌었다고 기능 회귀 검사를 통과한 것으로 보지 않는다. 타입 검사·빌드·관련 테스트와 실제 브라우저 확인 결과를 구분한다.

## 기술·저장·구현 원칙

현재 프로젝트의 프레임워크·라우터·패키지 관리자·스타일 도구를 먼저 확인하고 유지한다. 신규 프로젝트가 필요한 별도 상황의 기존 권장안은 React + TypeScript + Vite, 일반 CSS/CSS Modules, Context + useReducer, localStorage, Vitest이다. 이 UI 개편을 이유로 기술 스택을 바꾸거나 서버·실제 인증을 추가하지 않는다. 이번 N 규칙의 시연 로그인은 포함한다.

업무 상태 전환 함수는 다음 데이터를 계산하고, 중앙 명령 처리에서 검증·저장을 수행한다. 저장에 성공한 뒤 화면 상태를 확정하고 실패하면 이전 업무 상태와 폼 입력을 유지한다. 직접 UI 컴포넌트 곳곳에서 저장·집계를 수행하지 않는다.

미션·사용자·결과물·제출 버전·피드백·역할·상태의 ID와 타입을 유지한다. 화면 변경 때문에 업무 데이터 복사본을 만들거나 과거 제출을 덮어쓰지 않는다. 최초 실행 또는 확인받은 초기화에서만 시드 데이터·날짜를 만든다. 렌더링·새로고침으로 알림·이력·시드를 재생성하지 않는다.

문서 버전과 저장 schemaVersion은 별개다. 레이아웃 변경만으로 저장 키·형식을 변경하지 않는다. 불가피한 변경은 읽기 호환·변환·백업·실패 복구를 구체화한다. 호환되지 않는 데이터를 자동 삭제해 해결하지 않는다.

앱 내 메뉴·미션·사용자 이동은 공통 이동 함수가 접근 범위와 미저장 입력을 확인한다. 시연 로그인·다른 계정 체험은 실제 서버 인증이 아니다. 로컬 저장은 같은 브라우저·출처에서만 쓰며 다른 기기·브라우저·동시 탭과 동기화하지 않는다. 배포해도 데이터가 자동으로 사용자 간 공유되지 않는다.

기존 테스트가 있으면 활용한다. 상태 전환·집계·저장 실패의 핵심 규칙을 의미 있게 검증하고 실제 화면 이동을 브라우저에서 확인한다. 도구 제약으로 실행하지 못한 검사와 통과한 검사를 구별한다. 첫 단계 소스를 읽지 못하면 앱을 수정했다고 보고하지 않는다.

## 신규 요구사항 N-01~07

### N-01 공개 홈과 로그인 후 공통 홈

첫 실행은 session=null, P-01. 공개 헤더·서비스 설명·포스터·핵심 활동·이용 과정·가이드 연결을 표시한다. 로그인 여부에 따라 같은 홈에 계정·업무 바로가기·개인 다음 행동을 추가한다. 로그인 완료는 관리자도 P-01이며, 별도 개인 대시보드로 자동 전환하지 않는다. 정적 소개 데이터에는 허위 실적·후기를 쓰지 않는다.

### N-02 시연 로그인·계정 검증

P-12의 역할 선택은 해당 역할의 계정 목록만 보여주는 UI다. 실제 role 값은 계정 레코드에서 가져온다. 빈 계정·존재하지 않는 ID·역할 불일치로 로그인할 수 없다. 로그인 버튼을 중복 눌러도 업무 데이터나 시드가 재생성되지 않는다. 실제 이메일·비밀번호·소셜 인증·가입·복구 기능은 없다.

선택 완료 전 기존 세션을 바꾸지 않는다. 계정 체험 취소 시 이전 상태 복귀. 완료 후 이전 개인·미션·폼 선택을 비우고 새 계정 홈으로 이동한다. session은 메모리 상태이며 저장소·URL·쿼리 파라미터에서 임의 권한을 복원하지 않는다.

### N-03 접근 검사와 요청 목적지

공개 P-01·12·13을 제외한 업무 페이지는 로그인·역할·소속·담당·대상 여부를 검사한다. 미구현 단계도 접근을 차단한다. 비로그인 보호 경로 요청은 내부 ID만 pendingDestination으로 기억하고 P-12에 일반 로그인 안내를 표시한다. arbitrary URL을 목적지로 저장하지 않는다.

로그인 성공 후 홈에서 목적지의 권한·존재·구현 여부를 다시 검사한다. 유효하면 ‘선택했던 기능으로 이동’ 또는 피드백 연결 버튼을 보여준다. 이동·취소·로그아웃·잘못된 계정 로그인 시 목적지를 제거한다. 유효하지 않은 대상의 제목·개인 정보를 미리 노출하지 않는다. 로그인하지 않은 뒤로가기·직접 경로·새로고침도 같은 검사를 적용한다.

### N-04 로그아웃·미저장 이탈

앱 내 로그아웃·계정 체험·메뉴·가이드 이동 전에 미저장 입력을 검사한다. 취소하면 현재 위치·세션·입력을 유지한다. 승인하면 임시 입력·선택 개인·목적지·세션을 해제하고 공개 홈. 업무 기록·저장 키는 그대로다. 로그아웃 후 보호 화면을 다시 요청해도 내용이 보이지 않는다.

### N-05 메뉴와 홈 바로가기

로고는 항상 P-01. 공개 방문자는 크루 활동 항목을 볼 수 있지만 선택 시 로그인 안내. 크루원·크루장은 자기 크루 홈·미션·구현된 소통, 관리자는 구현된 운영 관리. 한 크루만 있으면 중간 선택 없이 이동한다. 복수 소속은 미확정이며 임의 가입·전환 정책을 추가하지 않는다.

헤더는 모바일 메뉴 열기/닫기, 현재 위치, 키보드 동작을 제공한다. 비로그인·다른 역할에서 관리자 메뉴가 보이지 않을 뿐 아니라 페이지 진입도 막는다. 홈 요약 숫자는 업무 기록에서 계산한다.

### N-06 이용 가이드

P-13은 정적 콘텐츠와 목차 앵커로 구성한다. 공개 내용: 서비스 소개·로그인·크루 찾기·미션 제출·피드백 반영·선택적 게시·성과·FAQ. 크루장 안내는 등록·리뷰. 관리자 세부 절차는 관리자 로그인 후에만 데이터 조회·렌더링한다. CSS로 숨긴 내부 콘텐츠를 공개 DOM에 넣지 않는다.

안내의 실제 기능 버튼은 같은 이동·권한 함수를 사용한다. 미구현 기능은 후속 제공 설명만 하고 작동하는 버튼을 만들지 않는다. 가이드에는 검색·CMS·진도 추적·자동 완료 표시를 추가하지 않는다. 목차와 섹션 ID가 일치하고 작은 화면에서 제목이 가려지지 않는다.

### N-07 상태와 기술 범위

업무 데이터는 기존 localStorage, 시연 session·pendingDestination·임시 입력은 메모리, 공개 카피·가이드는 정적 데이터로 분리한다. 앱 전체 새로고침 시 세션·임시 입력은 사라져도 업무 데이터는 유지한다. 이전 선택 사용자 저장값이 있더라도 첫 접속 인증으로 취급하지 않는다.

기존 라우터는 재사용한다. 없으면 명시적인 페이지 상태로 구현할 수 있으나 직접 URL을 지원한다고 보고하지 않는다. 실제 배포 전에 제공하는 경로·새로고침·뒤로가기에서 공개·보호 상태와 서버 fallback을 확인한다. 이 문서의 로그인은 보안이 검증된 계정 시스템이 아니다.

## 신규 인수 조건 V-01~12

- V-01: 처음 열면 공개 홈. 계정 이름·크루 내부 기록·관리 메뉴가 보이지 않고 로그인과 가이드가 보인다.
- V-02: 크루원·크루장·관리자 각각 로그인해 모두 같은 홈으로 돌아온다. 이름·메뉴·바로가기만 역할에 맞게 달라진다.
- V-03: 홈의 상단 메뉴에서 크루 홈·미션·상세·퀵 리뷰로 이동하며 각 페이지의 목적과 배치가 다르다.
- V-04: 비로그인 보호 페이지 요청→로그인→홈→허용된 목적지 버튼. 다른 계정이면 해당 대상 내용을 노출하지 않는다.
- V-05: 가이드 공개 구간은 비로그인 이용 가능, 목차 이동이 작동한다. 관리자 내부 안내는 일반 사용자 DOM에 없다.
- V-06: 로그아웃은 업무 데이터를 삭제하지 않는다. 뒤로가기·직접 요청으로 이전 개인 화면이 노출되지 않는다.
- V-07: 입력 중 로그아웃·가이드·계정 이동을 취소하면 입력·세션 유지. 승인하면 입력만 버리고 저장된 기록 유지.
- V-08: 존재하지 않는 계정·역할 불일치는 로그인 불가. 소속 없는 계정은 홈·가이드와 배정 없음 안내만 제공한다.
- V-09: 새로고침 후 비로그인, 재로그인 후 이전 업무 기록·버전·날짜가 그대로다. 시드 중복 생성 없음.
- V-10: 390px·1280px 및 키보드로 헤더·로그인·가이드·필수 행동을 확인한다. 긴 제목·메뉴·포스터가 넘치지 않는다.
- V-11: 미구현 성과·소통·운영 메뉴 및 관련 업무 버튼이 없다. 이미 구현된 후속 기능은 보존된다.
- V-12: 기존 F-02~10과 T 핵심 결과·저장 실패·집계를 보존한다. 홈 추가나 색상 변경만으로 구조 개편 완료라고 보고하지 않는다.

V는 실제 앱에 적용한 뒤 실행할 인수 조건이다. 현재 문서·와이어프레임이 모든 V나 T를 통과했다는 뜻이 아니다.
