## 6-A 결정 (첫 테스터 피드백 반영, 사용자 확정)

기준 문서 v0.6에서 제외했던 일부 기능을 사용자 결정으로 넣는다 (F-10 수정·삭제, 크루 안 비공개 글, F-11 마감 임박 알림).

| 항목 | 결정 |
| --- | --- |
| 미션 현황 | 크루장 미션 상세·운영 관리 합계·크루장 대시보드에서 막대와 더하기 식을 뺀다. '대상 n · 검토 대기 n · 보완 요청 n · 완료 n · 미제출 n'. 크루장은 숫자를 누르면 그 상태의 퀵 리뷰 목록으로 간다(미션 상세, 미션 목록 표). 관리자 대시보드의 그래프는 그대로 |
| 마감 임박 | 마감 24시간 전부터 미제출자 알림함에 '마감 임박'(자동, 계산). 크루장은 미션 상세에서 '재촉 알림 보내기'(마감 전 미제출자, 같은 미션 하루 한 번). 모두 앱 안 알림, 외부 발송 없음 |
| 게시판 | 커뮤니티(크루장 공지·글, 크루원 글) / QnA(크루원 질문 → 크루장 답변). QnA 비공개 질문은 작성자·크루장·담당 관리자만. 관리자는 운영 관리에서 크루 QnA를 읽기 전용으로 본다. 전체 게시판은 정책을 정한 뒤 |
| 공지 강조 | 크루 홈 맨 위 진한 테두리 카드, 로그인 홈 개인 구역에 최근 공지 한 줄 |
| 수정·삭제 | 작성자 본인. 수정하면 '수정됨'. 댓글이 있는 글은 '삭제된 글'로 남기고, 댓글은 '삭제된 댓글'로 남긴다. 크루장 답변이 달린 질문은 수정 잠금 |
| QnA 알림 | 내 질문에 크루장 답변이 달리면 알림함 'QnA 답변' |
| 저장 형식 | v5 → v6: 재촉 기록만 추가 (글·댓글의 새 칸은 선택 칸). v5 원래 값은 `crew-prototype/backup-v5`로 백업 |

## 6-B 결정 (광고 제안, 사용자 확정)

기준 문서 F-09(관리자 기록만, 수락·거절·후보 추천 제외)를 사용자 결정으로 확장한다. 실제 진행·계약·정산·외부 발송은 여전히 하지 않는다.

| 항목 | 결정 |
| --- | --- |
| 입력 | 브랜드명·제품명·카테고리(선택)·제품 설명·광고 형식(브랜디드 콘텐츠/커머스/공동구매)·단가·희망 업로드 일자(달력)·비고, 관리자 내부 메모(선택) |
| 받는 사람 | 관리자 → 크루원 여러 명 또는 크루장 여러 명 (한 제안에 섞지 않음). 담당 크루 안에서, 카테고리로 거르기 |
| 응답 | 받는 사람별 수락·거절. 거절 사유: 일정이 안 맞아요 / 카테고리가 안 맞아요 / 단가가 맞지 않아요 / 기타(직접 입력). 수락 후 철회 없음. 결과는 관리자 알림함 |
| 크루장 | '받은 제안'(크루원 '내 제안'과 같은 위치). 자기 크루원 여러 명에게 전달 기록(연락 수단·메모), 추천(여러 명·사유), 대리 응답(진행할 크루원 0명 이상). 크루원에게 직접 간 제안은 크루장에게 보이지 않음 |
| 추천 | 관리자가 확인하고 고른 크루원에게 같은 조건의 새 제안을 보낸다 (이미 받은 사람은 빠짐). 추천만으로는 아무것도 가지 않음 |
| 무응답 | 보낸(또는 마지막으로 다시 알린) 지 2일 지나면 관리자 알림함에 안내 + `다시 알림`. 같은 사람에게 하루 한 번. 받는 사람에게는 '응답 대기'로만 보임 |
| 수정·취소 | 누구든 응답하기 전까지만 조건 수정(받는 사람은 고정, 수정 알림). 취소는 언제든, 받는 사람 모두에게 알림, 기록은 '취소됨'으로 남김 |
| 진행 기록 | 수락하면 받는 크루원별 진행 기록(진행 상태 협의 중)이 생기고, 진행 상태·수익 기록은 기존처럼 관리자만 (개인 상세 › 광고·커머스 제안). 기존 기록은 '이전 기록'으로 남김 |
| 화면 | 관리자: 운영 관리 › 제안 탭 (목록·새 제안·상세). 개인 상세에서 '이 크루원에게 새 제안 보내기' |
| 저장 형식 | v6 → v7: 제안·받는 사람·전달·추천 목록만 추가. 기존 제안 기록은 그대로. v6 원래 값은 `crew-prototype/backup-v6`로 백업 |

| 관리자 | 운영 관리 › 크루 구성원에서 'Q&A게시판'을 읽기 전용으로 (탭 없음) |

## 6-C 결정 (크루방·홈·우수 사례·크루 둘러보기, 사용자 확정)

| 항목 | 결정 |
| --- | --- |
| 크루방 | 메뉴 이름 '크루 홈' → '크루방'. 머리: '{크루} 크루방', 카테고리, 현재 상황 한 줄(크루장·크루원 수·진행 중 미션·이번 주 마감), 소개. 카드: 공지(맨 위, 크루 공지 + 운영 공지) · 미션(크루원: 달성률 원형·이번 주 할 일·남은/완료 미션·할 일 3개 / 크루장: 미션 배정 n건 상태 숫자·검토할 미션) · 최근 게시물(자유게시판) · Q&A(크루원: 내 질문과 답변 여부 / 크루장: 답변을 기다리는 질문). 로드맵 형태는 넣지 않음 |
| 로그인 홈 | 포스터를 빼고 '내 현황' 카드 + 큰 `크루방으로`(관리자는 `운영 관리로`). 크루원: 내 미션 달성률·이번 주 할 일·응답 대기 제안·새 알림 / 크루장: 검토 대기·마감 임박 미제출·응답 대기 제안·새 질문 / 관리자: 응답 없는 제안·검토 지연 크루·추천 도착. 카드를 누르면 해당 화면. 최근 공지 한 줄과 다음에 할 일은 유지 |
| 이번 주 할 일 | 미제출·보완 요청 중 마감이 7일 안이거나 지난 것 |
| 관리자 공지 | 운영 관리 › 공지 탭. 제목(40자)·내용(300자)·보여줄 담당 크루. 그 크루의 크루방 공지 카드(내용까지)와 구성원 알림함 '운영 공지'. 지우면 내려감(기록은 삭제 표시로 남김) |
| 우수 사례 두 단계 | 지정할 때 성과 한 줄(40자, 공개 홈) + 학습 포인트(80자, 크루 전용 페이지, 이전 '한 줄 평'). 크리에이터에게 동의 요청 알림 → 미션 상세에서 동의/공개하지 않기. 동의 후 언제든 철회, 철회하면 바로 내려감. 지정한 사람은 결과 알림. 동의 칸이 없는 이전 기록은 동의 대기로 봄 |
| 공개 범위 | 공개 홈 배너(누구나, 최대 3건): 카테고리·크루, 성과 한 줄, 조회수는 '크리에이터 직접 입력, 확인일'과 함께. 크리에이터 이름·링크·학습 포인트 없음, `크루로 로그인하고 자세히 보기`. 우수 사례 페이지: 로그인한 모든 크루 구성원 |
| 크루 둘러보기 | 공개 홈(로그인 후에도): 카테고리, 크루 이름, 소개 한 줄, 키워드(최대 3), 크루원 수·이번 달 미션 수·공개 사례 수. 크루장 이름·가입 버튼 없음, '크루 합류는 운영팀이 따로 안내해요'. '새 카테고리 크루 준비 중' 카드. 소개·키워드는 운영 관리 › 크루 구성원 아래 '공개 크루 소개'에서 관리자만 고침 |
| 저장 형식 | v7 → v8: 관리자 공지 배열만 추가. 사례의 성과 한 줄·동의, 크루 키워드는 선택 칸. v7 원래 값은 `crew-prototype/backup-v7`로 백업 |

## 6-C 후속: 공지 게시판 · 크루장 대시보드 (사용자 확정 견본)

| 항목 | 결정 |
| --- | --- |
| 공지 게시판 | 커뮤니티 탭 `공지 · 자유게시판 · Q&A게시판`. 처음 여는 탭은 자유게시판. 공지 탭에는 크루장 공지와 그 크루에 보낸 운영 공지가 최신순으로 함께 |
| 머리표 | `[운영 공지]` 로고 주황 바탕 + 로고 글자색, `[크루장 공지]` 진한 먹색 바탕 + 흰 글자. 글자로도 구분하고, 테두리만 있는 카테고리 태그와 다르게 바탕을 채움. 공지 탭·크루방 공지란·로그인 홈 공지 줄에 같은 머리표 |
| 쓰는 곳 | 크루장: 공지 탭 `공지 쓰기`(자기 크루). 관리자: 운영 관리 › 공지(크루를 골라 한 번에). 크루원은 쓰기 버튼 없음. 자유게시판의 '공지' 구분은 없앰 (이미 올라온 크루장 공지는 데이터 변환 없이 공지 탭에 보임) |
| 댓글 | 크루장 공지는 댓글 가능. 운영 공지는 읽기 전용, 문의는 Q&A게시판으로 (`Q&A게시판에 질문하기`) |
| 알림 | '크루장 공지'·'운영 공지' 알림은 공지 탭의 그 공지로 연다 |
| 크루장 대시보드 | '조회수 합계 추이'를 뺀다(게시물 수·한 편의 큰 숫자·입력 시점에 좌우돼 할 일을 알려주지 못함). 대신 ① 미션별 성과: 게시 / 대상, 게시물당 조회수 중앙값, 가장 높은 게시물(확인일, 직접 입력). 조회수가 입력된 게시물이 2편보다 적으면 비교하지 않음 ② 피드백 효과(최근 미션 3개): 1차 제출에 바로 완료된 비율, 보완 요청 뒤 다시 제출한 비율, 다시 제출까지 걸린 날 중앙값 — 제출·피드백 기록에서 계산. 주차별 제출 상태 표와 크루원 성과 표는 그대로. 크루원별 성장(선택안)은 넣지 않음 |
| 저장 형식 | 변경 없음 (v8) |

| 도움말 | 화면을 설명하는 보조 문장은 제목 오른쪽 (?) 도움말로 접음: 미션 목록, 커뮤니티, 내 제안·받은 제안, 내 성과, 우수 사례, 크루 성과 관리. 마감·금액·필수 표시·오류·시연 안내(실제 발송 안 함)는 접지 않음 |

## UI 개선 B: 미션 상세 · 크루장 첫 화면 (사용자 확정, 2026-11-13 검토안)

| 항목 | 결정 |
| --- | --- |
| 미션 상세 (크루원) | 제목·상태, 마감·제출 형식 한 줄. 제출할 수 있으면 목표·기준(접힘) → 보완 요청이면 크루장 피드백 → 입력란·`제출하기`가 처음부터 펼쳐짐. 두 번째 '제출하기' 클릭과 '기준을 확인하고 제출해 주세요' 반복 안내는 없앰. 빈 칸 제출은 칸 아래 이유 표시. 제출 뒤에는 상태와 제출한 내용(링크·텍스트)을 보여주고, 목표·기준(접힘)·이력이 이어짐 (Google Classroom 과제 제출 참고) |
| 크루장 크루방 '처리할 일' | 맨 위에 `미션 만들기`(주 버튼)와 숫자 3개: 검토 대기 · 미제출 · 답변 대기. 숫자를 누르면 아래 목록이 그 상태로 좁혀짐 (Linear 상태별 목록 참고) |
| 목록 한 줄 | 검토 대기: 이름 · 미션 · n차 제출 · 시각(2일 넘으면 '2일 넘게 기다림'), `검토하기` → 그 크루원의 퀵 리뷰. 미제출: 마감 지남 → 마감 24시간 안 → 마감 전으로 묶고, 급한 줄에 `미션 보기`(재촉·미제출 안내는 미션 상세에서). 답변 대기: 이름 · 질문, `답변하기` |
| 미제출 숫자 | 아직 첫 제출이 없는 사람 모두 (사용자 확정). 숫자 아래 '마감 지남 n · 24시간 안 n' |
| 답변 대기 | 크루장 댓글이 1개 이상이면 답변 완료 (사용자 확정) |
| 크루장 크루방 카드 | 처리할 일 → 공지 → 미션 현황(크루 전체 상태 숫자) → 최근 게시물. Q&A 카드는 처리할 일과 겹쳐 크루원에게만 |

## UI 개선 C: 광고 제안 입력·응답 (사용자 확정, 2026-11-13 검토안)

| 항목 | 결정 |
| --- | --- |
| 입력 묶음 | 제품 정보(브랜드명·제품명·카테고리·제품 설명, 모두 필수) · 제안 조건(광고 형식·단가·희망 업로드 일자, 모두 필수) · 추가 내용(비고·내부 메모, 선택, 접힘) (Tally 폼 참고) |
| 광고 형식 | 드롭다운. 저장값은 이름이 바뀌어도 그대로인 내부 코드(ad·commerce·group_buy) |
| 단가 | 입력하는 동안 천 단위 쉼표, 뒤에 '원'. 저장은 숫자. 빈 값과 0원 구분. 중간 자리를 고쳐도 커서 유지 |
| 빠진 항목 | 버튼을 막지 않고, 맨 위 '빠진 필수 항목이 있어요' + 칸마다 이유. 칸을 고치면 그 칸의 오류는 바로 지움 |
| 응답 | 같은 크기의 `수락`(주황)·`거절`(테두리). 크루원 수락 → 확인 창. 크루장 수락 → 진행할 크루원 고르기 → `크루장으로 수락하기`. 거절 → 사유 고르기 → `거절 보내기`(검정, 주황 아님) / `돌아가기` |
| 조건 변경 | 조건을 고칠 때마다 바뀐 항목(받는 사람에게 보이는 조건만)과 시점을 남기고 조건 번호를 1씩 올림. 받는 사람이 응답하기 전이면 '조건이 바뀌었어요 · 시점 (n번째 조건)'과 바뀐 항목을 보여줌. 응답에는 몇 번째 조건에 응답했는지 남김. 화면을 연 뒤 조건이 바뀌었으면 응답을 막고 다시 확인하게 함. 누구든 응답하면 수정 잠금(기존 규칙) |
| 저장 형식 | 변경 없음 (v8). 조건 이력·응답 조건 번호는 선택 칸 |
