# 코딩 적용 지시문 v0.6

## 적용 원칙

기존 코드를 보관하고 실제 소스를 제공한다. 공유 URL만으로 소스·데이터 구조를 읽었다고 가정하지 않는다. 통합 Markdown 하나 또는 개별 문서 00~06을 제공한다. 이전 스케치·명세를 새 기준과 중복 첨부하지 않는다.

이번 기준은 공개 홈→시연 로그인→같은 홈→상단 메뉴→기능이다. 기존 퀵 리뷰 배치를 서비스 전체에 적용하지 않는다. P-01은 소개형 공통 홈이고 P-12·13이 추가된다. 기존 F 업무 규칙·데이터 보존과 신규 N/V 규칙을 함께 적용한다.

## A — 기준 전환 확인 요청

```text
첨부한 CREW_BUILD_BRIEF_v06.md를 이번 제작 기준으로 사용해.
아직 코드를 수정하지 말고 현재 소스를 읽어 다음을 제시해.

1. 비로그인 홈 → 시연용 로그인 → 같은 홈 → 메뉴 → 핵심 기능의 페이지·라우트 계획.
2. 크루원·크루장·관리자 모두 로그인 후 홈으로 돌아오며, 역할별 메뉴와 접근 범위를 어떻게 적용할지.
3. 기존 미션·제출·피드백·버전·성과·제안·소통 중 현재 구현된 것을 새 화면 어디에 연결할지.
4. 공개 홈, 로그인, 가이드, 크루 홈, 미션 목록, 독립 상세, 퀵 리뷰, 관리자 화면의 배치 차이.
5. 기존 저장 키·ID·업무 규칙을 보존하고 세션 상태만 분리하는 계획.
6. 수정할 파일·재사용할 컴포넌트·검증할 기존 T 및 신규 V 항목.

‘승인된 스케치 배치를 유지’와 ‘모든 화면을 목록+상세 병렬로 구성’ 지시는 폐기해.
색상과 홈 배너만 바꾸고 나머지 구조를 그대로 두는 계획은 불충분해.
현재 소스를 읽을 수 없다면 구체적으로 필요한 파일을 알려줘. 읽지 않은 코드를 읽었다고 하지 마.
실제 인증·서버·카카오·결제·정산을 이번 범위에 추가하지 마.
```

## B — 기존 코드에 적용 요청

```text
확인한 계획대로 v0.6을 현재 코드에 적용해.

1. 먼저 공개 홈·로그인·로그인 후 같은 홈·상단 메뉴·가이드·접근 처리의 골격을 연결해.
2. P-02~06에 현재 미션·제출·리뷰 기능을 연결하고 기존 F 규칙과 T 테스트를 보존해.
3. 현재 구현된 후속 기능은 P-07~10에 연결해. 없는 후속 기능을 일괄 추가하지 마.
4. 홈은 소개 문구·정적 콘셉트 포스터·활동 소개·가이드 연결로 구성해.
   로그인 상태에 따라 계정과 업무 바로가기만 바뀌고, 소개 홈 자체는 유지해.
5. 로그인은 사전 등록 가상 계정만 사용하고 실제 비밀번호는 받지 마.
   로그인 성공은 항상 홈, 로그아웃은 개인 표시와 세션만 제거하고 업무 기록은 보존해.
6. 기존 저장 형식 변경이 불가피하면 변경 이유·변환·백업·복구 계획을 먼저 명시해.
7. 실제 구현에서 가짜 작동 버튼·예정 기능 메뉴를 노출하지 마.
8. V 신규 흐름·기존 T·저장 실패·반응형을 검사하고, 통과한 검사와 못 한 검사를 구별해.

첫 단계가 끝나면 실제 홈→로그인→홈→기능 화면으로 이동할 수 있는 상태를 보여줘.
기능 전체를 한 페이지에 나열하거나 앵커만 붙여 독립 화면을 대체하지 마.
```

## 새 프로젝트가 필요한 경우

현재 구조가 심하게 결합돼 있으면 새 프로젝트를 제안할 수 있으나 데이터·업무 규칙까지 다시 발명하지 않는다. 소스 재사용과 재작성의 범위·이유를 비교하고, 새 출처로 이동할 때 데이터 가져오기 여부를 명시한다. 실제 새 구축은 사용자의 해당 선택 이후 진행한다.

## 구현 완료 보고

바뀐 페이지와 기능 연결, 유지한 데이터, 통과한 테스트, 실제 브라우저에서 확인한 화면 폭, 남은 제한을 보고한다. 시연 로그인을 실제 보안·여러 사용자 서비스로 표현하지 않는다. 문서 작업이나 와이어프레임을 실제 앱 수정 완료로 보고하지 않는다.
