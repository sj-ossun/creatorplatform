# 전체 서비스 설계 v0.6

## 1. 서비스와 출발점

크루장과 크루원이 카테고리별 크루에서 미션·제출·피드백·소통을 이어가고, 관리자는 동일 기록을 여러 크루와 개인 단위로 조회하는 웹 서비스다. 홈은 처음 방문한 사람에게 서비스의 목적을 소개하고 로그인·기능 탐색으로 연결한다.

사용자 승인: 공개 홈에서 시작, 역할별 로그인 마련, 로그인 후 같은 홈 복귀, 상단 메뉴를 통해 기능 선택, 소개 배너·글·이미지 배치, 스크롤형 가이드, 시연용 로그인으로 첫 프로토타입 구현.

설계 제안: CREW 가칭, 아래 카피와 색상, 크루당 대표 카테고리 1개, 메뉴 구체 명칭. 실제 회사 브랜드나 운영 정책의 확정으로 간주하지 않는다.

## 2. 정보 구조

```text
공통 웹사이트
├─ P-01 홈 [공개 / 로그인 후 같은 페이지]
│  ├─ 서비스 소개·브랜드 포스터·활동 소개
│  ├─ 로그인 전: 로그인하고 시작하기 → P-12
│  └─ 로그인 후: 역할별 바로가기·내 다음 행동
├─ P-12 시연 로그인 [공개]
│  └─ 크루원 / 크루장 / 관리자 → 가상 계정 선택 → P-01
└─ P-13 이용 가이드 [기본 안내 공개]
   ├─ 목차 → 시작 / 크루 / 미션 / 피드백 / 게시·성과 / FAQ
   └─ 관리자 운영 절차 [관리자 로그인 후만]

크루 활동 [로그인한 크루원·크루장]
├─ P-02 크루 홈
├─ P-03 미션 목록
│  ├─ P-06 미션 등록 [크루장]
│  └─ P-04 미션 상세
│     ├─ P-05 퀵 리뷰 [담당 크루장]
│     └─ P-07 게시·성과 [본인 검토 완료 결과물, 2차]
└─ P-08 소통 [3차]

운영 관리 [로그인한 담당 관리자, 2차]
└─ P-09 다중 크루 현황 → 구성원
   └─ P-10 크리에이터 상세 / 활동·성과·제안

P-11 진행자 시연 도구 [로그인 후 보조 영역]
└─ 초기화 / 알림 예시 / 다른 계정 체험(P-12 경유)
```

P-01은 이전 개인 홈을 대체한다. P-02~11 번호는 보존하고 P-12·13을 신설한다. 새로 로그인할 때마다 관리자를 포함해 P-01에 도착한다. P-09는 로그인 후 메뉴에서 선택하는 화면이다.

## 3. 전역 메뉴 계약

| 상태 | 로고 | 크루 활동 | 이용 가이드 | 운영 관리 | 계정 |
|---|---|---|---|---|---|
| 비로그인 | 홈 | 표시; 선택하면 로그인 안내 | 공개 안내 | 숨김 | 로그인 |
| 크루원 | 홈 | 크루 홈·미션·구현된 소통 | 공통·크루원 안내 | 숨김 | 이름·역할·로그아웃 |
| 크루장 | 홈 | 크루 홈·미션·구현된 소통 | 공통·크루장 안내 | 숨김 | 이름·역할·로그아웃 |
| 관리자 | 홈 | 숨김; 담당 크루는 운영 관리에서 조회 | 공통·관리자 안내 | 구현 후 표시 | 이름·역할·로그아웃 |

크루 활동은 드롭다운이다. 클릭·키보드로 열고 선택·Escape·다른 영역 클릭 시 닫는다. 모바일에서는 메뉴 펼치기 안에 같은 항목을 세로 배치한다. hover만으로 기능을 열지 않는다.

미구현 소통·성과·운영 기능은 실제 제품 메뉴에서 숨긴다. 설계 검토 화면에서 단계별 영역을 보여줄 경우 ‘설계 예시’로 구분한다. 1차만 구현된 상태에서 관리자도 로그인은 가능하지만 홈에 ‘운영 기능은 다음 단계에서 제공’ 안내를 보이고 작동하지 않는 운영 버튼은 만들지 않는다.

## 4. 로그인 전후 홈

공통 순서: 헤더 → 로그인 사용자 바로가기(로그인 후만) → 소개 문구와 포스터 → 핵심 활동 3개 → 이용 과정 → 가이드 연결 → 푸터.

- 헤더는 언제나 찾기 쉽다. 로그인 버튼을 소개 이미지 안에 넣지 않는다.
- 로그인 사용자 바로가기는 짧은 한 구역으로 구성한다. 크루원은 내 크루·미션, 크루장은 내 크루·검토할 미션, 관리자는 구현된 운영 관리.
- 개인 다음 행동은 본인의 미제출·보완 요청 또는 크루장의 검토 대기 미션을 기존 원본에서 조회한다. 마감 오름차순, 동률은 ID. 최대 3개 요약 후 해당 목록으로 연결한다.
- 홈은 가입자 수·매출·성장률·성공 후기 등 확인되지 않은 수치를 넣지 않는다. ‘수익 보장’처럼 검증되지 않은 결과도 약속하지 않는다.
- 로그아웃하면 개인 구역만 제거하고 같은 공개 홈으로 간다. 업무 기록은 지우지 않는다.
- 공개 홈과 로그인 홈에 별도 데이터·컴포넌트 복사본을 만들지 않는다.

## 5. 공개·보호 경계

P-01·12·13의 공개 안내는 비로그인 접근 가능하다. 미션·크루 활동·제출·성과·내부 제안은 로그인 및 소속·대상 검사를 거친다. 메뉴 숨김만으로 접근 검사를 대신하지 않는다.

비로그인 상태에서 보호된 페이지를 열면 상세 정보를 표시하지 않고 P-12로 안내한다. 로그인 완료 후에는 항상 P-01로 복귀한다. 요청했던 목적지가 유효하면 홈에서 ‘선택했던 기능으로 이동’ 버튼을 제공한다. 자동으로 업무 페이지로 보내지 않는다. 역할이나 대상이 맞지 않으면 버튼을 만들지 않고 해당 역할의 정상 메뉴를 제공한다.

로그인 후 다른 역할의 보호 화면 접근은 접근 불가 상태와 홈 복귀를 제공한다. 존재 여부를 추측할 수 있는 타인 미션명·제안·사용자 개인정보를 오류 메시지에 넣지 않는다.

## 6. 가이드의 구조

P-13은 한 페이지를 스크롤하는 문서형 화면이다. 상단 목차는 섹션 앵커로 이동한다. 일반 설명과 크루원·크루장 절차는 공개할 수 있으나 회사 내부 제안·관리 절차의 상세는 관리자 로그인 후만 렌더링한다.

공개 안내: 서비스 목적 → 시연 로그인 → 내 크루·미션 찾기 → 제출·피드백 → 선택적 성과 기록 → FAQ. 기능이 미구현이면 ‘후속 제공’ 안내만 하고 비활성 업무 버튼을 넣지 않는다. 크루장 절차에는 등록·퀵 리뷰를 설명한다.

초기에는 코드 또는 Markdown 기반 정적 콘텐츠다. CMS·검색·가이드 편집·완독 추적·튜토리얼 강제 완료는 없다. 화면 이름·입력 조건이 바뀌면 가이드와 기능 명세를 같은 변경에서 갱신한다.

## 7. 크루와 기능의 확장

카테고리(푸드·뷰티 등)는 크루 분류다. 상단의 기능 메뉴와 혼동하지 않는다. 카테고리마다 전용 화면 코드를 복제하지 않고 공통 크루·미션 페이지가 데이터를 표시한다. 복수 크루 소속·공개 모집·카테고리 탐색·추천은 별도 정책 확인 후 추가한다.

새 기능 배치 원칙: 개인의 여러 활동을 요약하면 홈; 크루 전체가 사용하면 크루 하위; 미션 수행이면 상세 하위; 결과물 기록이면 성과 하위; 회사 내부 운영이면 관리자 하위. 예정 기능을 담기 위해 빈 메뉴를 미리 만들지 않는다.

## 8. 페이지 유형과 데이터 분리

공개 소개 홈은 여유 있는 2열 히어로와 섹션 구성, 가이드는 읽기 중심 단일 흐름, 목록은 탐색, 상세는 이해·행동, 리뷰는 대기열+작업, 운영은 비교·조회에 맞춘다. 퀵 리뷰를 앱 전체 템플릿으로 사용하지 않는다.

공통 컴포넌트: GlobalHeader, CrewMenu, AccountMenu, Breadcrumbs, Hero, FeatureSection, GuideToc, StatusBadge, MissionCard, EmptyState, FormField. 이름은 예시이고 기존 같은 책임의 컴포넌트가 있으면 재사용한다.

상태를 세 부분으로 분리한다: 업무 데이터(기존 저장소), 시연 세션(currentUserId 또는 null), 탐색·미저장 폼. 홈 소개·가이드·포스터는 정적 콘텐츠다. 세션을 업무 저장 스키마에 섞지 않는다. 같은 원본으로 홈·미션·운영 숫자를 계산한다.

## 9. 구현 단계

0. 현재 코드 보관·구조 파악. 기존 데이터와 기능의 재사용 여부 확인.
1. 공통 헤더·P-01 공개/로그인 홈·P-12 시연 로그인·P-13 기본 가이드·접근 처리·모바일 탐색을 먼저 연결.
2. P-02~06 및 F-01~06·F-08 계산·F-11A를 연결하고 기존 기능 테스트. 가이드의 실제 버튼도 연결.
3. P-07·09·10과 F-07~09 구현. 관리자 가이드와 홈 운영 바로가기 활성화.
4. P-08 및 F-10·11B 구현. 소통 메뉴와 관련 가이드 활성화.

이미 구현된 이후 기능은 삭제하지 않는다. 초기 화면 구조 검토를 위해 전체 단계의 와이어프레임을 보여주는 것과 일괄 기능 구현은 구별한다.

## 10. 이번에 새로 확정하지 않은 사항

실제 브랜드명·로고·포스터 원본, 실제 인증 제공자·회원가입·비밀번호 복구, 복수 소속 정책, 공개 크루 모집, 실제 카카오 연동, 정산·수익 배분, 개별 기기에서 함께 쓰는 베타 인프라는 미확정이다. 이번 시연을 멈추지 않고 가칭·가상 계정으로 진행한다.
