# 크리에이터 크루 플랫폼 디자인 시스템 v0.4

## 1. 이 문서를 쓰는 법

바이브코딩 도구에 `prototype-spec.md`, 이 문서, `tokens.css`를 함께 넣는다. 도구에는 12장의 지시문을 붙여 넣는다.

- 공통 색·서체·간격·컨트롤 크기의 코드 원본은 tokens.css다. 문서의 값은 설명용 사본이며 함께 갱신한다. 컴포넌트는 역할 토큰을 쓴다. 선 두께·아이콘 도형·비율·반응형 분기·컴포넌트 고유 배치는 직접 값이 가능하다. 반복되는 치수는 토큰으로 올린다.
- preview.html은 정적 디자인 견본이다. 여러 역할·상태는 서로 다른 시점의 독립 예시이며 같은 저장소를 공유하는 실행 앱이 아니다. 저장·알림·역할 전환·접근 검증은 앱에서 별도로 구현한다.
- 첨부안 채택과 밝은 오렌지 방향은 사용자 지정이다. #FF7A00은 제작 기본값이며 회사 공식 HEX 확정을 뜻하지 않는다. 나머지 치수·배치는 테스트로 조정한다.
- 컴포넌트 이름은 6장의 이름을 그대로 쓴다. `preview.html`에 같은 이름의 클래스로 조립 예시가 있다.
- 스토리보드 v0.2의 진한 초록 버튼은 이 문서의 주황으로 대체한다. 화면 배치(목록|상세 병렬, 왼쪽 메뉴, 상단 역할 전환)는 스토리보드를 따른다.
- 다크 모드, 브랜드 일러스트, 마케팅 페이지는 이번 범위가 아니다.

## 2. 디자인 방향

크리에이터의 촬영 현장에서 카메라 위 탈리 라이트(tally light)는 “지금 이 카메라가 돌아간다”는 단 하나의 신호다. 이 플랫폼의 주황이 그 역할을 한다. 크루원에게는 “지금 내가 할 일”, 크루장에게는 “다음에 볼 제출물”을 가리키는 신호로만 켜진다. 나머지는 차분한 청회색 업무 화면이다. 청회색은 주황의 보색 쪽으로 기울어 있어 주황이 적게 쓰여도 또렷하게 보인다.

화면의 주인공은 기록이다. 제출, 피드백, 수정본이 지워지지 않고 위로 쌓이는 모습이 그대로 보이게 한다(명세서 F-06).

## 3. 네 가지 원칙

1. **주황은 지금 할 일.** 한 화면 영역(목록 패널, 상세 패널, 대화상자 각각)에 주황 버튼은 최대 하나다. 상태와 선택 행·메뉴는 중립색 또는 전용 상태색을 쓴다. 밝은 오렌지는 주요 행동·행동이 있는 NextUp 막대·로고 점에만 사용한다. 링크·초점·버튼 경계는 대비를 확보한 짙은 오렌지를 별도 사용한다.
2. **상태는 모양과 글자로.** 네 가지 제출 상태는 기호 모양이 모두 다르고 항상 글자와 함께 나온다. 흑백으로 출력해도 구별돼야 한다(명세서 7.3).
3. **점선은 시연 영역.** 역할 전환, 알림 미리보기, 시연용 기한처럼 실제 인증·발송 대신 시연임을 알리는 영역은 점선과 문구로 구별한다. 시연용 기한도 제출 시각과 비교하는 예시 데이터다. 저장된 기록은 실선이다. 점선을 장식이나 구분선으로 쓰지 않는다(명세서 2장 실제 동작/시뮬레이션 구분).
4. **기록은 쌓인다.** 수정본은 이전 버전을 덮지 않는다. 최신 버전이 맨 위에 흰 바탕으로, 과거 버전과 그 피드백은 아래에 회색 바탕으로 남는다.

## 4. 토큰

토큰은 두 층이다. 원색 팔레트(`--orange-500`, `--ink-700` 등)는 `tokens.css` 안에서만 쓰고, 컴포넌트는 역할 토큰(`--action-bg`, `--text-muted` 등)만 쓴다. 회사 색이 바뀌어도 역할 토큰 연결은 그대로 둔다.

### 4.2 글꼴

- **원티드 산스 가변(Wanted Sans Variable)** 한 벌만 쓴다. 굵기 400–1000 가변, 숫자 등폭(tnum) 지원, OFL 라이선스.
- 설치: `npm i wanted-sans` 후 `src/main.tsx`에서 `import 'wanted-sans/fonts/webfonts/variable/split/WantedSansVariable.css'` (한글을 나눠 받아 첫 로딩이 가볍다).
- 대체 글꼴 순서는 `--font-sans`에 정해져 있다.

| 단계 | 크기 / 행간 | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| `figure` | 32 / 1.1 | 820 | 관리자 집계 숫자, 조회수 |
| `page` | 22 / 1.35 | 760 | 화면 제목 (미션명, 크리에이터 이름) |
| `title` | 17 / 1.45 | 760 | 패널 제목, 지금 할 일 제목, 대화상자 제목 |
| `body` | 16 / 1.6 | 400 | 본문, 입력값, 버튼(640) |
| `meta` | 14 / 1.5 | 400–640 | 목록 보조줄, 칩, 표 머리 |
| `caption` | 14 / 1.5 | 520 | 태그, 각주 |

규칙
- 17px 이상 제목은 자간 `--tracking-tight`(-0.012em), 집계 숫자는 `--tracking-figure`(-0.02em).
- 본문은 `word-break: keep-all`로 어절 단위 줄바꿈. 긴 URL만 `overflow-wrap: anywhere`로 끊는다(기본 스타일에 포함).
- 숫자가 세로로 맞아야 하는 곳(집계, 조회수, 시각, 버전 번호)은 `font-variant-numeric: tabular-nums`. `<time>`과 `.num`에 기본 적용돼 있다.
- 본문 줄 길이는 `--measure`(36em, 한글 약 36자) 이하. 피드백, 수정 내용, 게시글 본문에 적용한다.
- 고정폭(모노스페이스) 글꼴, 영문 대문자 라벨, 기울임은 쓰지 않는다.

### 4.3 간격·모서리·깊이·움직임

- **간격** 4px 단위: `--space-1`(4) `2`(8) `3`(12) `4`(16) `5`(20) `6`(24) `8`(32) `10`(40) `14`(56). 패널 안쪽 여백은 PC 24, 모바일 기본 16·좁은 화면 12.
- **모서리는 위계마다 다르다.** 태그 4px, 버튼·입력·탭 8px, 패널·대화상자 12px, 제출 상태 칩만 완전한 둥근 모양. 모든 요소를 같은 반경으로 통일하지 않는다.
- **깊이** 면은 1px 선으로 나눈다. 그림자 `--shadow-float`는 화면 위에 뜨는 것(확인 대화상자, 저장 결과 알림)에만 쓴다. 카드마다 그림자를 넣지 않는다.
- **움직임** 상태 변화 120ms, 위치 이동 200ms. 의도된 움직임은 하나뿐이다: 퀵 리뷰에서 처리한 행이 검토 대기 목록에서 빠질 때 200ms 동안 흐려지며 높이가 접힌다. 페이지 진입 애니메이션, 카드 올림 효과는 넣지 않는다. `prefers-reduced-motion`이면 모두 0ms(`tokens.css`에 포함).

## 5. 상태 표현

### 5.1 제출 상태 4종

| 화면 글자 | 코드값 | 기호 | 기호의 뜻 |
| --- | --- | --- | --- |
| 검토 대기 | `pending_review` | 반쯤 찬 원 ◐ | 내 손을 떠나 크루장을 기다리는 중 |
| 보완 요청 | `revision_requested` | 마름모 ◆ | 다시 크루원 차례 |
| 완료 | `completed` | 꽉 찬 원 ● | 내부 검토 끝 |
| 미제출 | `not_submitted` | 빈 원 ○ | 아직 결과물 없음 |

- 표시 순서는 항상 위 순서다(명세서 F-04 필터 순서). 필터, 집계 범례, 분포 막대, 크루별 개수 모두 같다.
- 기호는 `tokens.css`의 `.status-glyph[data-status=…]`로 그린다. 기호는 `aria-hidden="true"`이고 뜻은 옆 글자가 전달한다.
- 코드값은 명세서에 영문 값이 없어 이 문서가 제안한 것이다. 구현에서 다른 문자열을 정했다면 `tokens.css`의 `data-status` 선택자와 `--status-*` 토큰 이름을 그 값으로 바꾼다.
- 완료는 “내부 검토 끝”이다. 게시됨, 성공, 수익 발생처럼 보이는 표현(축하 아이콘, 체크 애니메이션)을 붙이지 않는다(명세서 6.1).
- ‘우수’, 점수, 순위 표시는 만들지 않는다(F-05, F-08).

### 5.2 모양 언어

| 모양 | 뜻 | 예 |
| --- | --- | --- |
| 둥근 칩 (`--radius-pill`) | 제출 상태 4종 **전용** | 검토 대기, 완료 |
| 사각 태그 (`--radius-tag`, 실선 테두리) | 기록의 속성 | 기한 후 제출, 수동 입력, 질문, 광고, 협의 중 |
| 사각 태그 진한 바탕 | 공지 (목록 맨 위 고정 글) | 공지 |
| 점선 테두리 | 실제로 일어나지 않는 것 | 시연 도구, 알림 미리보기, 시연용 기한 |
| 회청색 바탕 + 자물쇠 | 관리자에게만 보임 | 내부 메모 |

### 5.3 그 밖의 표시 규칙

- **기한 후 제출**: 사각 태그 `기한 후 제출`. 빨강·경고 기호를 쓰지 않는다. 벌점이 없는 단순 사실이다(A-06).
- **시연용 기한**: 점선 사각 태그 `시연용 기한`을 마감 일시 바로 옆에 둔다(7.1).
- **성과 값 세 가지**(F-07, T-06): `0회`는 집계 숫자 굵기로, `미집계`는 숫자 자리에 보조색 글자로, `미게시`도 같은 방식으로 쓴다. 빈 조회수를 `0`이나 `-`로 바꿔 보이지 않는다. 실제 성과 관찰 기록이 있을 때만 확인일과 수동 입력 태그를 붙인다. 미게시·게시 정보만 저장한 미집계에는 확인일을 만들지 않는다. 회고만 있는 관찰은 미집계와 실제 확인일을 함께 표시한다.
- **제안 진행 상태 6종**(F-09: 제안 준비, 제안 전달, 협의 중, 진행 확정, 보류, 종료): 모두 같은 중립 사각 태그. 제출 상태 색을 빌려 쓰지 않는다. ‘제안 전달’ 옆에 발송 아이콘을 두지 않는다.
- **대상자 전용 미션**(F-10, T-09): 자물쇠 + `대상자 전용 미션` + 비활성 버튼 `열 수 없음`. 미션 제목은 보이지 않는다.
- **저장 실패**: 저장 버튼 바로 위에 오류 띠(`--error-bg`, `--error-fg`, `role="alert"`). 상태 칩과 집계는 바꾸지 않는다(F-01, 6.1).

## 6. 컴포넌트

각 컴포넌트는 `src/components/<이름>/` 아래 `<이름>.tsx`와 `<이름>.module.css`로 만든다. 괄호 안은 `preview.html`의 클래스다.

### 6.1 SimBar 진행자 시연 바 (`.simbar`)
- 화면 맨 위 최소 44px, `--bg-inverse` 바탕. 앱 바깥의 도구라는 것이 한눈에 보여야 한다.
- 왼쪽부터: 점선 태그 `시연 도구`, `역할` 선택, `예시 사용자` 선택, 안내 `실제 로그인이 아니에요`, 오른쪽 끝 `예시 데이터 초기화`(밑줄 글자 버튼).
- 예시 사용자 선택지는 `이름 (크루)` 형식. 역할은 선택지 필터이며 예시 사용자를 선택하면 역할·소속·담당 크루가 함께 결정된다. 역할 필터 변경만으로 업무 사용자를 불일치 상태로 만들지 않는다(F-01).
- 초기화는 확인 대화상자(6.16)를 거친다. 제목 `예시 데이터를 처음 상태로 되돌릴까요?`, 버튼 `계속 사용` / `초기화하기`.
- 좁은 화면에서는 필요한 만큼 여러 줄로 접힌다. 높이를 고정하지 않는다. 숨기지 않는다.

### 6.2 AppHeader, Nav (`.appheader`, `.nav`)
- 헤더 56px: 로고 `CREW` + 주황 점, 현재 크루 이름, 오른쪽에 현재 사용자 `지훈 크루장`.
- 왼쪽 메뉴 224px. 현재 메뉴는 `--bg-subtle` 바탕 + 왼쪽 3px 잉크 선 + 굵게. 주황이 아니다.
- 메뉴 옆 숫자는 처리할 건수(크루장: 검토 대기 수)만. 0이면 숫자를 숨긴다.
- 역할별 메뉴

| 역할 | 메뉴 |
| --- | --- |
| 크루원 | 내 미션, 크루 소통 |
| 크루장 | 미션, 퀵 리뷰, 크루 소통, 알림 미리보기 |
| 관리자 | 전체 크루, 알림 미리보기 |

- 1200px 미만에서 왼쪽 메뉴는 헤더 아래 가로 스크롤 메뉴가 된다.

### 6.3 Button (`.btn`)

| 종류 | 모양 | 쓰는 곳 |
| --- | --- | --- |
| `action` | 주황 바탕, 진한 글자 | 영역의 지금 할 일 하나: 제출하기, 수정본 제출하기, 완료 처리, 보완 요청 남기기, 미션 등록, 다음 검토 대기 |
| `secondary` | 흰 바탕, 선 | 그 밖의 모든 실행: 취소, 구성원 보기, 상태 바꾸기, 문구 넣기 |
| `strong` | 잉크 바탕, 흰 글자 | 확인 대화상자의 진행 버튼: 이동하기, 초기화하기 |
| `quiet` | 밑줄 글자 | 덜 중요한 이동: 이전 버전 보기, 예시 데이터 초기화 |

- 높이 최소 44px, 글자 16px 640, 모서리 8px. 작은 버튼 `sm`은 32px, PC 목록·표 안에서만. 모바일 터치 영역은 44px 이상으로 확장한다.
- **저장 중**: 실제 button disabled와 처리 중 가드를 함께 사용하고 aria-busy, 진행 표시, 저장 중 문구를 제공한다. 초점 유지를 위해 aria-disabled를 쓸 때도 클릭·Enter·Space를 명시적으로 차단한다. ARIA 속성만으로 중복 실행을 막았다고 간주하지 않는다(F-03·05).
- **비활성**: `--bg-subtle` 바탕, `--text-disabled` 글자. 왜 비활성인지 버튼 글자나 바로 옆 문장으로 말한다(예: `남은 검토 대기 없음`).
- 글자 뒤에 화살표(→)를 붙이지 않는다. 새 탭으로 열리는 링크만 외부 링크 아이콘을 붙인다.

### 6.4 Field 입력 (`.field`, `.input`, `.textarea`)
- 구조: 라벨(16px 640) → 입력 → 도움말 또는 오류. 라벨은 입력 위에 둔다. 자리표시 글자를 라벨 대신 쓰지 않는다.
- 필수 표시 대신 **선택 항목에 `(선택)`**을 붙인다. 이 앱은 필수 입력이 대부분이다.
- 입력 높이 44px, 테두리 `--border-input`, 초점 시 `--focus-ring` 2px.
- 오류: 테두리와 안쪽 1px를 `--error-fg`로, 입력 아래 `!` 원 기호 + 오류 문장. `aria-invalid="true"`, `aria-describedby`로 연결. 저장을 누른 뒤 표시하고, 수정한 입력을 재검증하고 오류가 해소된 경우에만 안내를 지운다.
- 날짜·시간 입력은 브라우저 기본 `datetime-local`을 쓰고, 옆 도움말에 한국 시간을 적는다. datetime-local에는 시간대가 없으므로 값을 Asia/Seoul 시각으로 해석한다. 호스트 시간대를 그대로 쓰지 않는다.
- 조회수 입력은 `inputmode="numeric"`. 비워 둘 수 있다는 것을 도움말에 쓴다: `비워 두면 미집계로 남아요`.

### 6.5 StatusChip, Tag (`.chip`, `.tag`)
- StatusChip: 최소 높이 28px, 기호 + 상태 글자, 14px 640. `data-status`로 색이 결정된다. 칩 안에 다른 글자(버전, 시각)를 넣지 않는다.
- Tag: 최소 높이 26px, 14px 520, 사각. 변형은 기본(실선), `sim`(점선), `notice`(잉크 바탕), `internal`(회청색 바탕 + 자물쇠).

### 6.6 FilterTabs 상태 필터 (`.filters`)
- 퀵 리뷰 상단. 각 탭은 기호 + 상태 글자 + 개수. 기본 선택은 검토 대기(F-04).
- 선택된 탭: 잉크 글자 굵게 + 아래 2px 잉크 선. 주황이 아니다.
- tablist와 연결된 tabpanel, 선택 탭 tabindex=0·나머지 -1, aria-selected·aria-controls를 제공한다. 좌우 화살표·Home·End 키를 지원한다. 좁은 화면에서는 가로 스크롤.

### 6.7 ListRow 제출자 목록 행 (`.row`)
- 1줄: 상태 기호, 이름(640), 오른쪽 끝 제출 시각. 2줄: `2차 제출`, 필요하면 `기한 후 제출` 태그.
- 검토 대기 목록은 제출 시각이 빠른 순서. 패널 머리에 `먼저 제출한 순서`를 적는다.
- 선택된 행: `--bg-subtle` + 왼쪽 3px 잉크 선. 각 행의 실제 버튼으로 선택하고 Tab·Enter·Space 동작을 제공한다. 단순 목록에 aria-selected를 임의로 붙이지 않는다. listbox를 쓰면 option·roving tabindex를 포함한 전체 패턴을 구현한다.
- 처리 직후 행은 4.3의 움직임으로 목록에서 빠지고, 상세 패널은 처리 결과(6.10)를 계속 보여준다.

### 6.8 SplitView 목록|상세 (`.split`)
- 가용 본문 폭 800px 이상: 목록 약 280~300px | 상세 최소 480px(최대 760px). 960px viewport는 초기 분기이며 실제 공간이 부족하면 세로로 전환한다. 기본은 페이지 스크롤이며 이중 스크롤은 테스트 후 필요할 때만 적용한다.
- 960px 미만: 목록이 위, 상세가 아래로 쌓인다. 행을 누르면 상세로 스크롤하고, 상세 맨 위에 `목록으로` quiet 버튼을 둔다.
- 관리자 화면도 같은 구조를 쓴다(크루 구성원 목록 | 개인 상세). 별도 앱처럼 보이게 다른 배치를 만들지 않는다.

### 6.9 VersionTimeline 버전 기록 (`.versions`)
- 세로선 위에 버전마다 점. **최신 버전이 맨 위**, 진한 점 + 흰 바탕 상자. 과거 버전은 빈 점 + `--bg-app` 바탕 상자.
- 버전 머리: `2차 제출`(굵게), 제출 시각, 필요하면 `기한 후 제출`.
- 상자 안 정의 목록: `영상 링크` 또는 `제출 내용`, `수정한 내용`(2차부터), `설명`(있을 때).
- 그 버전에 남긴 피드백은 해당 버전 상자 바로 아래에 붙인다. 왼쪽 3px 선은 처리 결과의 `-line` 색, 머리에 작성자 + 상태 칩 + 시각. 피드백을 버전과 떨어진 댓글 영역에 모으지 않는다(명세서 6.2).
- 링크는 `--text-link` 밑줄, 새 탭(`target="_blank" rel="noopener"`), 외부 링크 아이콘. 영상 임베드는 하지 않는다(F-04).
- 버전이 셋 이상이면 최신과 바로 이전 버전만 펼치고 나머지는 `이전 버전 보기`로 접는다.

### 6.10 FeedbackComposer, ReviewResult (`.compose`, `.result`)
- 제목 `2차 제출 검토`처럼 어느 버전을 검토하는지 적는다.
- 처리 결과는 큰 라디오 두 개 `완료`, `보완 요청`. 선택하면 테두리 2px + 해당 상태 바탕색. 기본 선택은 없다.
- 문구 넣기 버튼 3개: `첫 장면 문구 넣기`, `메시지 전달 문구 넣기`, `다음 행동 문구 넣기`. 누르면 커서 위치에 문구를 넣고 그대로 고칠 수 있다. 글자 수 제한 없음(F-05).
- 입력 라벨은 선택에 따라 바뀐다. 보완 요청: `수정 방향` (필수). 완료: `피드백 (선택)`.
- 저장 버튼 글자도 선택에 따라 바뀐다: `완료 처리` / `보완 요청 남기기`. 아무것도 고르지 않았으면 비활성 `처리 결과를 고르세요`.
- 버튼 옆 안내: `저장하면 민지에게 보낼 알림 예시가 함께 만들어져요.`
- 처리 후에는 입력 영역 대신 ReviewResult(읽기 전용 회색 상자: 상태 칩 + `방금 처리했어요` + 피드백 본문)를 보여주고 그 아래에 `다음 검토 대기: 하늘`(action) 또는 비활성 `남은 검토 대기 없음`을 둔다(F-04, T-11).
- 최신 버전이 검토 대기가 아니면 입력 영역을 그리지 않는다(이전 대상 중복 피드백 방지).

### 6.11 NextUp 지금 할 일 (`.nextup`)
- 크루원 미션 상세 맨 위. 흰 패널 + 왼쪽 4px 오렌지 막대(미제출·보완 요청에만). 검토 대기·완료에는 중립색 선. 이 플랫폼에서 주황 막대는 이것 하나다.
- 내용: 상태 칩 + 미션명 → 제목(17px 760) → 피드백 본문 또는 할 일 설명 → 작성자·시각 → 주황 버튼.

| 상태 | 제목 | 버튼 |
| --- | --- | --- |
| 미제출 | 기준을 확인하고 제출해 주세요 | 제출하기 |
| 검토 대기 | 크루장의 검토를 기다리고 있어요 | 없음 (버튼 대신 제출 시각) |
| 보완 요청 | 수정본을 제출해 주세요 | 수정본 제출하기 |
| 완료 | 검토가 끝났어요 | 게시 기록 남기기 (secondary, 선택 작업이므로 주황 아님) |

### 6.12 Distribution 집계 분포 (`.dist`, `.bar`, `.legend`)
- 관리자 전체 크루 화면 맨 위. 숫자 타일 네 개를 따로 띄우지 않고 **한 줄 막대 + 범례**로 보여준다. 네 상태의 합이 대상 건수라는 사실(F-08 완료 기준)이 모양으로 보이게 하기 위해서다.
- 머리: `대상 5건`(17px 760) + 오른쪽에 조회 기준 `담당 크루 전체, 미션 마감일 기준 전체 기간`.
- 막대 12px, 상태 순서대로 칸을 나눈다. 미제출 칸은 빗금(색이 없어도 구별되게). `role="img"`와 전체 내용을 담은 `aria-label`.
- 범례 4칸: 기호 + 상태 글자 + 숫자(32px 820) + 단위. 단위는 개별 미션이면 `명`, 전체 미션이면 `건`(F-08).
- 크루별 행은 같은 막대를 8px로 줄여 쓰고, 0건인 상태는 개수 목록에서 뺀다.
- 숫자는 모두 공통 집계 함수의 결과로 그린다. 예시 총계를 글자로 박지 않는다(명세서 6.2).

### 6.13 MetricValue 성과 값 (`.metric`)
- 게시물마다 제목과 값을 배치한다. 실제 관찰 기록이 있을 때만 확인일과 수동 입력 태그를 붙인다. 기록이 없으면 미집계·미게시의 이유를 표시한다.
- 값은 5.3의 세 가지(숫자, `미집계`, `미게시`) 중 하나. 천 단위 쉼표, 단위 `회`.
- 같은 게시물의 관찰 기록이 여러 날짜면 최신 확인일 값을 크게, 이전 값은 펼쳐 보기 표로.

### 6.14 InternalNote 관리자 전용 메모 (`.internal`)
- `--internal-bg` 바탕, 머리에 자물쇠 + `내부 메모, 관리자에게만 보여요`.
- 크루장·크루원 역할에서는 컴포넌트 자체를 렌더링하지 않는다. 가리거나 흐리게 처리하지 않는다(F-09, T-07).

### 6.15 SimFrame 알림 미리보기 (`.simframe`)
- 점선 테두리 상자. 머리에 점선 태그 `알림 미리보기` + `실제로 보내지 않아요`.
- 안에 메시지 말풍선(앱 이름, 문구, `내 피드백 보기` 버튼)과 아래에 이동 정보 `받는 사람`, `여는 곳`, `누르면`.
- `내 피드백 보기`를 누르면 예시 사용자가 바뀐다는 사실을 `누르면` 줄에 적는다(F-11A).
- 미제출 안내 미리보기(F-11B)는 같은 상자에 대상자 이름 목록과 `대상 2명`을 보여준다. 0명이면 `지금 안내할 대상이 없어요`. ‘발송 완료’류 문구는 어떤 경우에도 쓰지 않는다.

### 6.16 ConfirmDialog 확인 대화상자 (`.dialog`)
- 가운데 뜨는 상자, 최대 380px, `--shadow-float`, 뒤 배경은 --overlay.
- 제목은 질문, 본문은 결과 한 줄, 버튼은 오른쪽 정렬: 머무는 쪽 `secondary`, 진행하는 쪽 `strong`.
- 저장하지 않은 입력이 있을 때 앱 안 이동(메뉴, 대상자, 미션, 예시 사용자, 초기화)에서 띄운다(명세서 6.1).
  - 제목 `저장하지 않고 이동할까요?` / 본문 `작성 중인 피드백은 사라져요.` / 버튼 `계속 작성`, `이동하기`
- 열리면 첫 버튼(머무는 쪽)에 초점, Esc로 닫힘, 초점이 상자 밖으로 나가지 않고 닫으면 호출 버튼으로 복귀한다. 본문은 현재 입력 종류에 맞춘다.

### 6.17 EmptyState, SaveNotice
- 빈 상태는 왼쪽 정렬 제목 + 다음 행동 한 문장 + 필요하면 버튼. 그림을 넣지 않는다.

| 상황 | 제목 | 다음 행동 |
| --- | --- | --- |
| 크루장, 미션 없음 | 아직 등록한 미션이 없어요 | `미션 등록` 버튼 (action) |
| 퀵 리뷰, 필터 결과 없음 | 보완 요청인 제출물이 없어요 | 다른 상태를 고르거나 다른 미션을 선택하세요. |
| 크루원, 배정 미션 없음 | 배정된 미션이 없어요 | 크루장이 미션을 등록하면 여기에 보여요. |
| 제안 이력 없음 | 기록된 제안이 없어요 | `제안 기록 추가` 버튼 (secondary) |
| 소통, 글 없음 | 아직 올라온 글이 없어요 | `질문 쓰기` 버튼 |

- 필터 결과가 비면 상세 패널도 빈 상태로 바꾼다. 처리 직후의 읽기 전용 결과와 섞지 않는다(T-11).
- 저장 성공: 화면 아래 가운데 작은 알림(`--shadow-float`, 잉크 바탕 흰 글자), 4초 뒤 사라짐, `role="status"`. 문구는 9.3 표를 따른다.
- 저장 실패: 5.3의 오류 띠. 자동으로 사라지지 않는다.

### 6.18 PostItem, MissionLink 소통 (`.post`, `.mlink`)
- 목록: 공지(진한 태그)가 위, 그 아래 질문. 각 구분 안에서 최신순(F-10).
- 글 행: 구분 태그 + 제목, 아래 `작성자, 날짜, 댓글 2`.
- 연결 미션은 글 본문 아래 선 상자. 대상자·담당 크루장에게는 미션명 + `미션 열기`, 그 외에는 5.3의 잠금 표시.

### 6.19 Tabs 개인 상세 탭
- 관리자 개인 상세의 `활동`, `콘텐츠 성과`, `광고·커머스 제안`. FilterTabs와 같은 모양(아래 잉크 선)으로 통일한다.

### 6.20 Icon
- 아이콘은 다섯 개뿐이다: 자물쇠, 외부 링크, 종(알림), 시계(선택), 체크(선택). 의존성을 늘리지 않도록 `src/components/Icon`에 인라인 SVG로 둔다. 14px, `currentColor`.

## 7. 화면별 적용

각 화면에서 주황 버튼이 무엇인지 먼저 정한다. 이 표에 없는 곳에 주황을 쓰지 않는다.

| 화면 | 배치 | 주황 (지금 할 일) | 핵심 컴포넌트 |
| --- | --- | --- | --- |
| SC-01 미션 목록·등록 | 목록 \| 등록 폼 | `미션 등록` (목록 위) / 폼에서는 `등록하기` | ListRow, Field, 대상자 체크 목록 |
| SC-02 퀵 리뷰 | FilterTabs + 목록 \| 상세 | `완료 처리` 또는 `보완 요청 남기기`, 처리 후 `다음 검토 대기` | FilterTabs, ListRow, VersionTimeline, FeedbackComposer |
| SC-03 내 미션 | 미션 목록 \| 미션 상세 (모바일 우선) | NextUp의 버튼 | NextUp, VersionTimeline, Field |
| SC-04 게시·성과 기록 | 상세 안 섹션 | `게시 기록 저장` / `성과 기록 저장` (입력 중일 때만) | Field, MetricValue |
| SC-05 크루 소통 | 글 목록 \| 글 상세 | `질문 쓰기` (크루장은 `글 쓰기`) | PostItem, MissionLink |
| SC-06 전체 크루 | Distribution + 크루 표 → 구성원 목록 | 없음 (조회 화면) | Distribution, 크루 표 |
| SC-07 크리에이터 상세 | 구성원 목록 \| 탭 상세 | 제안 탭의 `제안 기록 저장` (입력 중일 때만) | Tabs, VersionTimeline, MetricValue, InternalNote |
| SC-08 알림 미리보기 | 목록 \| SimFrame | 없음 | SimFrame |

- SC-01 대상자 선택은 크루 구성원 체크 목록 + `전체 선택`. 미션 생성 후 대상은 바꿀 수 없다는 것을 등록 버튼 위에 적는다: `등록 후에는 대상과 기한을 바꿀 수 없어요.`(A-04)
- SC-03 미션 기준 상자에는 목표·제출 기준, 제출 형식(텍스트/링크), 마감(+ 필요 시 `시연용 기한`)을 둔다. 제출 폼은 NextUp 버튼을 누르면 그 자리에서 펼친다.
- SC-04는 완료된 제출물 아래에서만 진입한다. 게시 URL 입력 위에 `검토용 공유 링크가 아니라 실제 게시물 주소를 넣어 주세요.`
- SC-06 필터(크루, 기간, 미션)는 Distribution 위 한 줄. 기간 도움말 `미션 마감일 기준, 한국 시간`.

## 9. 문구

### 9.1 말투
- 해요체. 짧고 구체적으로. 사과하지 않는다(‘죄송합니다’ 금지). 오류는 무엇이 잘못됐고 어떻게 고치는지 말한다.
- 버튼은 일어날 일을 그대로 쓴다. ‘확인’, ‘제출’ 같은 한 단어 대신 `완료 처리`, `수정본 제출하기`.
- 같은 행동은 끝까지 같은 이름이다. 버튼 `보완 요청 남기기` → 알림 `보완 요청을 남겼어요` → 상태 칩 `보완 요청`.

### 9.5 날짜·숫자
- 모든 시각은 한국 시간. `Intl.DateTimeFormat('ko-KR', { timeZone: 'Asia/Seoul', … })`로 만든다.
- 상세: `11월 8일(일) 21:40`. 목록: `11월 8일 21:40`. 해가 다르면 앞에 `2025년`.
- 상대 시각(‘3시간 전’)은 쓰지 않는다. 마감 전후를 정확히 따져야 하기 때문이다.
- 숫자는 천 단위 쉼표. 단위는 숫자 바로 뒤 작게: `1,284회`, `3건`, `2명`.

## 10. 접근성 확인

- [ ] 상태는 기호 + 글자 + 색. 흑백 화면 캡처로 네 상태를 구별할 수 있다.
- [ ] 본문 글자 대비 4.5:1 이상, 입력 테두리·초점 테두리 3:1 이상(실제 인접 배경·hover·pressed·선택 상태별 계산 및 화면 확인 필요).
- [ ] 주황 바탕에 흰 글자가 없다.
- [ ] Tab으로 모든 입력·버튼에 갈 수 있고 초점 테두리가 보인다. 목록은 실제 버튼의 기본 키보드 동작을, 탭은 완전한 탭 키보드 패턴을 제공한다.
- [ ] 오류는 `aria-invalid`와 `aria-describedby`로 입력과 연결된다. 저장 실패 띠는 `role="alert"`.
- [ ] 저장 결과 알림은 `role="status"`.
- [ ] 장식 기호는 `aria-hidden="true"`, 분포 막대는 `role="img"` + 글자 설명.
- [ ] 375px 폭에서 버튼·입력이 잘리지 않고 누르는 영역이 44px 이상.
- [ ] 동작 줄이기 설정에서 움직임이 꺼진다.

### 11.3 지켜야 할 것
- 공통 색·서체·간격은 역할 토큰을 사용한다. 고유 배치·도형·반응형 분기는 직접 값을 허용하되 반복되면 토큰으로 올린다. 변경 시 문서와 미리보기도 갱신한다.
- Tailwind, MUI, shadcn 등 다른 디자인 체계를 함께 넣지 않는다(명세서 11.1). 기존 프로젝트에 이미 있으면 그 위에 이 토큰 값만 옮긴다.
- 주황 버튼이 한 영역에 둘 이상 생기면 하나를 `secondary`로 바꾼다.
- 상태 글자와 색은 `domain/status.ts`와 `data-status`에서만 정한다. 화면마다 따로 쓰지 않는다.
- 저장이 끝나기 전에 성공 알림, 상태 칩 변화, 집계 변화를 먼저 보여주지 않는다(명세서 11.2).

## 12. 바이브코딩 도구에 붙여 넣을 지시문

```
첨부한 prototype-spec.md(기능 명세서 v0.3)를 기능 기준으로,
design-system.md와 tokens.css를 화면 기준으로 삼아 만들어 줘.

  저장 성공 후에만 상태·피드백·알림을 확정하고 실패하면 입력을 유지해.
  T-01~05·10·11과 중복·저장 실패·미저장 이동을 검증해.
```

## 13. 후속 확인

- **회사 공식 주황 hex**: 지금 값 `#FF7A00`는 임시다. 확정되면 4.1의 절차대로 교체한다.
- **로고**: 지금은 글자 `CREW` + 주황 점. 실제 로고 파일이 있으면 AppHeader만 바꾼다.
- **스토리보드 문구 차이**: 스케치의 `피드백 보내기`는 `완료 처리` / `보완 요청 남기기`로 바꿨다. 실제 메시지를 보내지 않으므로 ‘보내기’를 쓰지 않는다.
- **제출 상태 코드값**: 5.1의 영문 값은 제안이다. 명세서나 구현에서 정하면 그 값으로 맞춘다.
- **사용자 테스트 후 볼 것**: 크루원이 마름모(보완 요청)를 “내 차례”로 읽는지, 관리자가 빗금 막대를 미제출로 읽는지 관찰 기록에 남긴다.


## 14. 통합 업무·검증 규칙

- **저장:** 검증 → 다음 데이터 전체 저장 → 성공 시 화면 확정. 성공 토스트만 띄우고 저장을 생략하지 않는다.
- **실패:** 이전 업무 상태·집계를 유지하고 현재 입력을 보존한다. 오류를 해당 입력 또는 작업 영역에 표시한다.
- **중복:** 저장 중 버튼 비활성화와 처리 조건 검사로 중복 제출·피드백·알림을 막는다.
- **미저장 이동:** 메뉴·미션·대상자·예시 사용자·초기화에서 확인한다. 취소하면 입력·초점을 유지한다. 자동 임시저장을 새로 추가하지 않는다.
- **공개 범위:** 예시 접근 범위는 화면 직접 이동에도 확인한다. 메뉴 숨김만으로 데이터 분리를 대신하지 않는다. 실제 서버 보안으로 표현하지 않는다.
- **알림:** 피드백과 상태·알림 예시를 함께 저장한다. 과거 알림의 편집 가능 여부는 최신 업무 상태로 판단한다.
- **미구현:** 현재 묶음에 없는 기능을 동작하는 성공 화면으로 꾸미지 않는다.

### 검증 시나리오 연결

| 항목 | 명세 테스트 | 시각·동작 확인 |
| --- | --- | --- |
| 미션 등록 | T-01 | 대상자와 등록 결과, 초기화 후 다음 테스트 |
| 최초 제출·보완·재제출·완료 | T-02~05 | 네 상태·버전·읽기 전용·과거 피드백 |
| 성과 | T-06·12 | 0과 미집계, 게시만 저장, 확인일별 관찰 |
| 제안 | T-07 | 내부 메모·수동 상태 변경·이력 |
| 소통·관련 미션 | T-08·09 | 같은 크루 공개와 비대상 미션 비공개 |
| 저장·전환 | T-10 | 새로고침 후 동일 날짜·버전·상태 |
| 마지막 검토 | T-11 | 처리 결과 유지와 빈 필터 상세 비우기 |

초기 전체 집계: 대상 5건 = 검토 대기 1 + 보완 요청 0 + 완료 1 + 미제출 3. 민지 제출 후 2/0/1/2, 보완 후 1/1/1/2, 재제출 후 2/0/1/2, 완료 후 1/0/2/2. 순서는 검토 대기/보완 요청/완료/미제출이다. 이 값은 테스트 기대값이며 UI에 하드코딩하지 않는다.

사용자 관찰에는 성공 여부·막힌 지점·진행자 도움·소요 시간을 기록한다. 속도·리텐션·교육 효과·수익 개선을 검증했다고 주장하지 않는다.
### 제작 단계와 필수 예외

- 1차: F-01~06·F-08 계산·F-11A. 2차: F-07~09. 3차: F-10·F-11B·통합 점검. 1차에서도 기본 모바일·오류·빈 상태는 사용할 수 있어야 한다.
- 마감 뒤 최초 제출·재제출을 허용하고 기한 후 태그만 표시한다. 완료 후 재제출·검토 대기 중 임의 수정·과거 버전 삭제는 지원하지 않는다.
- 미션 생성 시 대상자를 고정하며 생성 후 대상·기한·형식 수정과 삭제는 지원하지 않는다.
- 최신 검토 대기 버전만 처리한다. 처리 후 상세에 읽기 전용 결과를 유지하고 빈 필터로 이동하면 상세를 비운다.
- 같은 크루 게시글·댓글 공개와 개인 제출·피드백 공개 범위를 구별한다. 관리자 내부 메모와 비대상 미션은 화면 직접 이동에서도 접근 범위를 검사한다.
- 게시 기록은 선택이다. 조회수·회고가 모두 없으면 관찰 기록을 만들지 않는다. 같은 확인일 수정·다른 확인일 추가와 조회수 null·0을 구별한다.
- 제안은 여섯 상태 중 어느 값으로도 수동 변경 가능하다. 같은 상태 재저장은 변경 이력을 늘리지 않으며 저장을 발송으로 표현하지 않는다.
- 최초 실행·명시적 초기화에서만 예시 날짜를 생성한다. 호환되지 않는 저장 버전을 자동 삭제하지 않는다. 초기화는 이 앱의 저장 키만 복원한다.
- T-01은 별도 확인 후 초기화한다. T-02~06 기대 집계에 추가 미션이 섞이지 않게 한다.
- 업무 로직·저장·집계를 컴포넌트와 분리하고 모든 역할이 같은 원본 데이터를 참조한다.
