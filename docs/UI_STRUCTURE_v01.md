# 크루 운영 플랫폼 — 메뉴·화면·데이터 분리 설계 v0.1

작성일: 2026-11-10
상태: 사용자 요청에 따른 구조 개편 설계안. 기존 기능 명세서 v0.3의 업무 규칙을 유지한다.

## 1. 이번 변경의 범위와 문서 우선순위

이번 작업은 기능 추가보다 화면 구조를 바꾸는 작업이다. 미션 탐색은 넓은 목록 화면, 크루원의 작업은 독립된 상세 화면, 크루장의 연속 검토는 목록·상세 병렬 화면으로 나눈다.

현재 Claude 공유 프로토타입은 브라우저에서 확인했으나 소스 코드를 전달받아 수정한 것은 아니다. 이 설계와 함께 제공하는 화면 미리보기는 기존 앱의 배포본이나 기능 테스트 완료본이 아니다.

### 변경되는 기존 지시

| 기존 기준 | 이번 개편 기준 |
|---|---|
| v0.3 4장: PC에서 목록과 상세 병렬 배치 | SC-02 퀵 리뷰에는 유지. SC-01 미션 목록과 SC-03 크루원 미션은 목록→상세 이동으로 분리 |
| v0.3 12.1: 승인된 스케치의 주요 배치 유지 | 제출·피드백·재제출 업무는 유지하되, 전체 메뉴·탐색 배치는 이번 문서를 우선 |
| 스케치 v0.2: 역할·초기화 도구 상시 노출 | 서비스 화면 밖의 접을 수 있는 시연 도구로 이동. 현재 예시 사용자·역할은 식별 가능하게 표시 |
| 퀵 리뷰를 항상 전역 메뉴로 노출 | 미션 선택 뒤 진입하는 작업 화면으로 배치. 홈의 검토 바로가기는 반드시 미션 ID를 포함 |

**충돌 해결:** 기능·상태·입력·접근 범위·저장·시험 기준은 v0.3 우선. 위 표에 명시한 메뉴·배치 변경만 이 문서 우선. 나머지 화면 스타일은 이 문서의 공통 규칙을 참고한다. DESIGN (2).md는 외형 참고이며 기능·메뉴 요구사항이 아니다.

기존 v0.3 11.2처럼 공유 URL·브라우저 뒤로가기·라우터 신규 설치를 이번 개편의 자동 필수 요구사항으로 올리지 않는다. 기존 프로젝트에 라우터가 있으면 사용하고, 없으면 공통 화면 이동 상태로 구현할 수 있다. 아래 경로는 화면 ID 관계를 설명하는 논리 경로다.

## 2. 유지하는 기능과 바꾸지 않는 업무 규칙

- F-01: 예시 사용자 선택, 동일 로컬 데이터 공유, 저장·초기화·오류 처리.
- F-02: 크루장 미션 등록, 텍스트/링크 형식, 생성 시 고정 대상자·기한.
- F-03~06: 최초 제출→검토→보완→재제출→완료, 이전 버전·피드백 보존.
- F-08 계산: 대상자-미션별 최신 상태 집계. 여러 미션 합산 단위는 '건'.
- F-11A: 실제 발송 없는 피드백 알림 예시와 대상 제출물 이동.
- 마감 이후 제출 허용과 기한 후 표시, 완료 후 재제출 금지, 검토 대기 중 수정 금지.
- 오류 시 입력 유지, 저장 성공 이후 상태 확정, 중복 이벤트 방지, 앱 내 이탈 시 미저장 입력 확인.
- 성과·제안·소통 등 이미 구현된 기능이 있으면 확인 후 보존한다. 화면에서 숨겨서 삭제한 것처럼 만들지 않는다.

현 단계에서 구현되지 않은 F-07~09 화면은 2차, F-10·F-11B는 3차 범위를 유지한다. 검색·랭킹·추천·채팅·모집·강의 판매·예약·실발송·외부 인증을 이번 개편에 추가하지 않는다.

## 3. 메뉴 구조

### 공통 틀

```text
상단: CREW | 홈 | 미션 | [현재 예시 사용자·소속]
       구현된 이후 기능만 해당 역할에 맞게 추가

본문: 현재 화면의 제목·위치 → 현재 업무 → 결과·다음 행동
하단 또는 보조 영역: 시연 도구(접기/펼치기)
```

메뉴가 적은 첫 버전에서 비어 있는 고정 사이드바를 사용하지 않는다. 크루가 하나인 사용자에게 크루 선택 드롭다운을 만들지 않는다. 기존 정책상 복수 크루인 사용자·관리자만 허용된 범위에서 크루를 고른다.

### 역할별 메뉴와 시작점

| 역할 | 첫 화면 | 현재 메뉴 | 이후 기능을 연결할 위치 |
|---|---|---|---|
| 크루원 | 홈: 내 다음 행동 | 홈, 미션 | 크루 소통; 게시·성과는 완료된 결과물에서 진입 |
| 크루장 | 홈: 검토할 미션·내 크루 | 홈, 미션, 기존 알림 예시 진입 | 크루 소통; 활동 조회는 해당 크루·미션 맥락 |
| 관리자 | 기존 단계에 맞는 시작 화면 | 2차 구현 후 운영 관리 | 전체 크루→구성원→개인 활동/성과/제안 |

관리자 화면이 아직 없으면 새 관리자 대시보드를 만들거나 다른 역할의 실제 권한으로 처리하게 하지 않는다. 기존 프로토타입의 단계 안내·역할 전환 동작을 보존한다.

**홈은 새 업무 데이터가 아니다.** 크루원 홈은 보완 요청/미제출인 배정 미션을, 크루장 홈은 검토 대기 건이 있는 미션을 기존 기록에서 읽어 보여준다. 첫 버전은 미션 마감 오름차순, 동률은 안정적인 ID 순서를 제작 가정으로 쓴다. 지난 마감은 숨기지 않으며 완료율·성장 점수·추천을 새로 만들지 않는다. 할 일이 없으면 빈 상태와 미션 목록 이동을 제공한다.

### 화면 연결

```text
홈
 ├─ 다음 행동 → 해당 미션 상세 또는 해당 미션 퀵 리뷰
 └─ 모든 미션 → 미션 목록

미션 목록
 ├─ 크루원: 미션 선택 → 미션 상세 → 제출/수정 폼
 └─ 크루장: 미션 선택 → 미션 개요 → 퀵 리뷰
                         ↑                 │
                         └── 미션 개요 ────┘
             미션 등록 → 등록 완료 → 해당 미션 퀵 리뷰(기존 동작 유지)

알림 예시 → 연결된 크루원·미션·버전의 피드백
2차: 완료 결과물 → 게시·성과 / 운영 관리 → 개인 기록
3차: 크루 소통 → 접근 가능한 관련 미션
```

## 4. 화면별 설계

### UI-01 홈 — 필요한 행동으로 바로 진입

- 상단: 사용자·크루 맥락, 짧은 인사, '이번에 할 일' 제목.
- 본문: 기존 미션에서 계산한 행동 목록. 제목·상태·기한·다음 행동 버튼.
- 보조 이동: 미션 목록 보기.
- 숨김: 장식용 성장 차트, 강의 추천, 후기·인증 배너, 존재하지 않는 커뮤니티 활동.
- 크루장 홈의 '검토하기'는 대상 미션을 선택한 상태로 퀵 리뷰에 연결한다.

### UI-02 미션 목록 — 탐색 화면

```text
미션                                 [미션 등록: 크루장만]
짧은 설명 / 현재 크루
[전체] [내 할 일 또는 검토할 미션] [완료]  ← 기존 데이터로 계산

미션 제목        미션 제목        미션 제목
목적 한 줄       목적 한 줄       목적 한 줄
상태·기한        상태·기한        상태·기한
[미션 보기]      [미션 보기]      [미션 보기]
```

- 크루원 카드: 자신의 최신 상태·마감·미션 형식. 미션별 결과물 수를 공개 랭킹으로 만들지 않는다.
- 크루장 카드: 해당 미션의 대상 인원·검토 대기 인원과 기한. 여러 미션을 합쳐 표시하면 단위를 건으로 바꾼다.
- 원본 목록의 접근 범위와 정렬을 먼저 보존한다. 새 UI의 필터는 조회용이며 업무 상태를 추가하지 않는다.
- 카드형은 기본 제안이다. 제목·마감·상태가 읽히는 것이 우선이며 썸네일은 필수가 아니다.
- 미션이 0개면 빈 화면을 제공한다. 목록이 적다고 가상의 운영 미션을 사용자 데이터에 몰래 추가하지 않는다.
- 3열→2열→1열로 줄어들고, 긴 제목은 줄바꿈한다.

### UI-03 크루원 미션 상세 — 독립된 단일 본문

```text
[← 미션 목록] / 미션 제목
미션 제목                          [최신 상태]
마감 / 제출 형식 / 크루

다음 행동 안내                     [제출하기 또는 수정본 작성]
목표·제출 기준
내 제출·피드백 이력
선택한 상태에 맞는 입력 폼
```

- 고정 미션 목록과 왼쪽 사이드바를 제거한다. 중앙의 읽기 편한 폭을 사용한다.
- 미제출: 기준과 첫 제출 행동. 설명은 선택이며 링크/텍스트 본문은 형식에 맞게 필수.
- 보완 요청: 관련 피드백을 먼저 보여주고 수정본·수정 내용 입력으로 연결.
- 검토 대기: 읽기 전용 제출 기록·검토 대기 안내. 제출 버튼을 다시 활성화하지 않음.
- 완료: 완료된 기록·피드백. 2차 구현 후에만 선택적 게시·성과 입력으로 연결.
- 과거 알림에서 진입하면 연결된 피드백을 강조하되 현재 상태도 함께 표시한다.
- 이력과 입력 영역을 무의미하게 여러 겹의 카드로 감싸지 않는다.

### UI-04 크루장 미션 개요 — 검토 이전 맥락

- 미션 목록에서 선택하면 기준·형식·고정 대상자·기한·현재 상태별 인원을 본다.
- '퀵 리뷰 열기'는 해당 미션 ID를 전달한다.
- 기존 미션 등록은 제목·기준·형식·대상자·기한 폼을 유지한다. 생성 후 수정·삭제 버튼은 추가하지 않는다.
- 개요는 목록에 붙은 영구 오른쪽 패널이 아니라 독립된 화면이다.

### UI-05 크루장 퀵 리뷰 — 작업 화면

- 상단 공통 메뉴를 유지하며, '미션 목록 / 미션 제목 / 퀵 리뷰' 위치와 돌아갈 경로를 제공한다.
- 상태 필터 → 제출자 목록 + 상세·이력·피드백의 병렬 배치를 유지한다.
- 업무 화면은 탐색 화면보다 간격을 조밀하게 할 수 있다. 모든 곳에 24px 패딩을 기계적으로 적용하지 않는다.
- F-04의 처리 직후 읽기 전용 결과, 다음 검토 대기 이동, 필터 변경 후 빈 상세를 그대로 유지한다.
- 작은 화면에서는 필터·목록 선택·상세 순으로 세로 배치한다.
- 알림 예시는 일반 서비스 메뉴에서 '실제 발송'처럼 보이지 않게 기존 시뮬레이션 표시를 유지한다.

### 이후 화면

성과 입력은 미션과 연결된 결과물의 하위 작업이다. 제안 이력은 관리자 개인 상세의 탭이다. 커뮤니티는 크루 공간이다. 모든 기능을 전역 메뉴로 하나씩 올리지 않는다.

## 5. 재사용할 화면·컴포넌트

파일명은 예시다. 기존 코드에 같은 책임의 구성요소가 있으면 재사용한다.

| 구분 | 예시 | 담당 책임 | 포함하지 않을 책임 |
|---|---|---|---|
| 공통 화면 틀 | AppShell, TopNavigation, DemoControls | 메뉴·현재 사용자·콘텐츠 슬롯 | 제출 상태 변경, 직접 저장 |
| 페이지 | HomePage, MissionListPage, MemberMissionPage, MissionOverviewPage, ReviewPage | 접근 범위 확인 후 데이터 연결·화면 구성 | 서로 다른 가짜 데이터 생성 |
| 공통 표시 | PageHeader, Breadcrumbs, StatusBadge, DeadlineText, EmptyState | 일관된 표시·이동 요청 | 문구로 업무 상태 추측 |
| 미션 표시 | MissionCard, MissionCriteria, MissionSummary | 같은 미션을 상황에 맞게 표현 | 상태별 결과를 별도 저장 |
| 제출 표시 | SubmissionHistory, FeedbackItem | 버전·피드백 관계 표시 | 과거 내용 덮어쓰기 |
| 입력 | MissionForm, SubmissionForm, FeedbackForm | 입력·오류 표시·저장 요청 | 직접 localStorage 쓰기 |
| 퀵 리뷰 | ReviewQueue, ReviewDetail | 목록 선택·검토 대상 표시 | 독립된 업무 상태 복제 |

카드형 목록과 표형 목록은 같은 조회 결과를 받아 표현만 바꿀 수 있어야 한다. 화면마다 전용 API·전용 데이터 모델을 새로 만들 필요는 없다. 모든 컴포넌트를 범용으로 추상화하지 말고 실제 두 군데 이상 쓰거나 책임이 분명한 경계를 먼저 분리한다.

## 6. 데이터와 화면 상태 분리

```text
업무 저장소: 미션 / 대상자 / 결과물 / 제출 버전 / 피드백 / 알림 예시
     ↓ 접근 범위를 적용한 조회 함수
홈·목록·상세·퀵 리뷰에 필요한 데이터
     ↓ 페이지가 표시 컴포넌트에 전달
사용자 입력 → 명령 처리 → 검증 → 다음 업무 데이터 계산
     → 저장 성공 → 공유 상태 확정 → 모든 조회 화면 갱신
     → 저장 실패 → 업무 상태 유지 + 입력·오류 안내 유지
```

### 서로 다른 세 가지 상태

| 상태 | 예시 | 원칙 |
|---|---|---|
| 업무 데이터 | 최신 제출 버전, 피드백, 고정 대상자 | v0.3 저장 형식·ID·관계 유지 |
| 탐색 상태 | pageId, missionId, selectedUserId, reviewFilter, listFilter | 같은 데이터의 표시 위치를 결정. 제출로 집계하지 않음 |
| 미저장 입력 | 폼 본문·URL·수정 설명, dirty 여부 | 업무 데이터로 저장 전 반영하지 않음. 이탈 확인 대상 |

예시 이동 요청:

```ts
type Screen =
  | { page: 'home' }
  | { page: 'missions' }
  | { page: 'mission'; missionId: string }
  | { page: 'review'; missionId: string; selectedUserId?: string }
  | { page: 'mission-create' }
  | { page: 'notification-preview' };
```

이는 책임 설명용 예시이며 기존 타입을 이 이름으로 강제 교체하지 않는다. 미션 제목·사용자 이름을 ID로 쓰지 않는다. 상태의 원본은 v0.3의 최신 제출·결과물이고 UI 배지·카운트는 조회 결과다.

조회 함수 예: `getVisibleMissions(userId)`, `getMemberMissionState(missionId, userId)`, `getReviewQueue(missionId, filter)`, `getMissionCounts(missionId)`. 같은 조건의 집계는 홈·목록·상세가 재사용한다. 함수 이름이 아니라 책임 경계가 중요하다.

### 화면 이동 규칙

1. 공통 이동 함수가 미저장 입력을 확인한다. 취소하면 현재 화면·입력을 유지한다.
2. 목적지 사용자·소속·대상자 범위를 확인한다. 주소·ID를 직접 넘겨도 메뉴 숨김만으로 판단하지 않는다.
3. 유효한 목적지일 때 화면 상태를 변경한다. 역할 전환 시 이전 역할의 선택 대상을 무조건 재사용하지 않는다.
4. 목록에서 상세로 갔다가 돌아오면 같은 사용자·크루 범위의 목록 필터를 유지한다.
5. 사용자·크루 범위가 바뀌면 유효하지 않은 필터·미션 선택을 해제한다.
6. 검토 중 다른 미션으로 이동하면 이전 미션의 선택 제출물을 상세에 남기지 않는다.

## 7. 디자인 규칙

- 서비스의 인상: 한국어 중심의 정돈된 크루 작업 공간. 홍보용 랜딩 페이지를 첫 진입으로 만들지 않는다.
- 중립적인 바탕과 흰색/어두운 테마의 명확한 콘텐츠 면. 포인트색은 선택·강조에 제한적으로 사용한다.
- 주요 행동은 채워진 진한 버튼, 보조 행동은 테두리·텍스트 버튼으로 구분한다. 첨부 참고서의 상충하는 CTA 지시를 그대로 병합하지 않는다.
- 상태·오류는 브랜드색과 별개의 의미를 가지며 반드시 상태명을 함께 쓴다.
- 본문 16px, 보조 14px, 작은 메타데이터 12px, 페이지 제목 28~32px를 시작값으로 삼고 한국어 줄바꿈을 점검한다. 별도의 유료·독점 글꼴을 요구하지 않는다.
- 여백은 4px 배수. 탐색 섹션 32~48px, 항목 간 16~24px, 작업 화면 8~16px를 기본으로 한다.
- 전체 콘텐츠 최대 폭은 약 1200px, 크루원 단일 상세는 약 840px를 제안한다. 퀵 리뷰는 넓은 작업 폭을 사용한다.
- 카드 제목·버튼·기한이 긴 경우 줄바꿈한다. 내용 잘림을 미관 때문에 허용하지 않는다.
- 예시 데이터·실발송 없음 표시는 숨기지 않되, 큰 검은 도구 막대가 서비스보다 먼저 보이지 않게 한다.

## 8. 기존 프로토타입 적용 순서

1. 현재 코드·명세·사용 중인 저장 키와 형식·이미 통과한 테스트를 확인하고 기준 상태를 남긴다. 공유 링크의 화면만 보고 코드 구조를 추측하지 않는다.
2. 기존 데이터 읽기·집계·명령·저장을 화면 바깥의 함수로 분리한다. 디자인 변경 전후 같은 입력에 같은 결과가 나오는지 확인한다.
3. 공통 화면 틀과 이동 함수부터 연결한다. 기존 화면을 임시로 그대로 넣어 데이터 동작을 확인한다.
4. 미션 목록을 독립 화면으로 만들고 크루원 상세를 분리한다. 기존 폼·이력·검증을 재사용한다.
5. 크루장 미션 개요와 퀵 리뷰를 연결한다. 처리 후 선택·빈 상태 동작을 유지한다.
6. 홈을 기존 데이터의 조회 화면으로 연결하고 시연 도구를 접을 수 있게 한다.
7. 기존 기능 회귀 검사와 새 이동·반응형 검사를 완료한다. 이후 묶음은 자동 착수하지 않는다.

CSS만 바꾸는 단계에서는 저장 schemaVersion을 바꾸지 않는다. 데이터 구조 변경이 불가피하면 기존 저장본을 읽는 변환 계획과 실패 복구를 별도로 작성하며, 저장 데이터를 자동 삭제해 해결하지 않는다.

## 9. 완료 기준

- 기존 기능 ID별 동작과 v0.3 테스트를 유지한다. UI 개편을 기능 검증 완료로 표현하지 않는다.
- 미션 목록에서 서로 다른 미션을 선택해도 상세·입력·검토가 올바른 ID에 연결된다.
- 목록 복귀·역할 전환·알림 이동에서 잘못된 사용자나 이전 제출물 내용이 남지 않는다.
- 첫 제출·보완 요청·재제출·완료 후 홈·목록·상세·공통 집계가 같은 최신 상태를 표시한다.
- 처리 직후 읽기 전용 결과 유지와 필터 변경 후 빈 상세를 구별한다.
- 미저장 입력 이탈 취소, 저장 실패, 중복 클릭, 새로고침 후 저장 유지가 기존처럼 동작한다.
- 390px와 1280px에서 핵심 입력·버튼·기한·오류가 잘리지 않고 키보드 사용이 가능하다.
- 데이터가 0·1·여러 개일 때, 긴 제목·긴 피드백에서도 목록과 상세를 사용할 수 있다.
- 화면이 달라졌다는 이유로 T-01 이후 테스트 초기화 등 기존 검사 전제를 바꾸지 않는다.

## 10. 전달할 파일과 현재 한계

코딩 AI에는 기능 명세서 v0.3, 이 문서, `IMPLEMENTATION_PROMPT.md`, 실제 현재 프로젝트 소스를 함께 제공한다. 이전 스케치·Udemy 참고서는 보조 자료로만 제공한다.

새 화면 미리보기는 탐색 구조를 비교하기 위한 별도 가상 데이터로 동작한다. 기존 Claude 프로토타입을 수정하거나 저장 데이터를 이관한 것이 아니다. 코드 통합은 현재 프로젝트 소스가 있는 환경에서 변경 지시문에 따라 진행해야 한다.
