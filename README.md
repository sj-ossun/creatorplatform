진행자 동반 사용자 테스트용 프로토타입입니다. 기준 문서는 `docs/`에 있습니다.

- 기능 기준: [docs/prototype-spec.md](docs/prototype-spec.md) (기능 명세서 v0.3)
- 화면 기준: [docs/design-system.md](docs/design-system.md) (디자인 시스템 v0.4), [src/styles/tokens.css](src/styles/tokens.css)
- **현재 제작 기준: [docs/v06/](docs/v06/00_START_HERE.md) (v0.6, 문서 00~06) + [디자인 결정](docs/v06/DESIGN_DECISIONS.md)** — 이하 문서는 이력 보관용: [CREW_BUILD_BRIEF_v04](docs/CREW_BUILD_BRIEF_v04.md), [UI_STRUCTURE_v02](docs/UI_STRUCTURE_v02.md), [UI_STRUCTURE_v01](docs/UI_STRUCTURE_v01.md) · [docs/IMPLEMENTATION_PROMPT.md](docs/IMPLEMENTATION_PROMPT.md)
- 정적 견본: [docs/preview.html](docs/preview.html) + [docs/preview.css](docs/preview.css) (`docs/tokens.css`와 같은 폴더에서 열기)
- 참고: [docs/references.md](docs/references.md), [docs/README.md](docs/README.md)

> 서버·실제 인증·실제 발송·정산이 없습니다. 로그인은 사전 등록 가상 계정으로 하는 시연 로그인이며 새로고침하면 풀립니다. 모든 데이터는 같은 브라우저의 localStorage에만 저장되고, 등장인물은 가상 인물입니다.

## 실행

```bash
npm install
npm run dev        # 개발 실행 http://localhost:5173 (포트 고정: localStorage는 출처별로 따로 저장됨)
npm run typecheck  # TypeScript 타입 검사
npm test           # Vitest 핵심 규칙 테스트
npm run build      # 타입 검사 + 배포 파일 빌드 (dist/)
```

설치 없이 링크로 나눌 단일 HTML 파일 만들기 (JS·CSS·글꼴을 한 파일에 포함):

```bash
npm run build:artifact   # → dist-artifact/crew-prototype.html
```

브라우저 시나리오 점검(선택, Playwright가 설치된 환경):

```bash
npm run build && npx vite preview --port 4173 --strictPort
NODE_PATH=$(npm root -g) npm run e2e   # 다른 터미널에서
```

## 화면 구조 (제작 기준 v0.6)

기본 여정: **공개 홈 → 시연 로그인 → 같은 홈 → 상단 메뉴 → 기능 페이지**. 1단계(화면 골격), 2단계(P-02~06 업무 화면), 3단계(P-07·09·10), 4단계(P-08 커뮤니티), 4.5단계(알림함·내 제안·우수 사례), 5단계(내 성과·크루 성과 관리·대시보드·수익 기록), 6-A(미션 현황 숫자·마감 임박/재촉 알림·QnA 분리·수정/삭제), 6-B(광고 제안 보내기·수락/거절, 운영 관리 정리), 6-C(크루방 카드·로그인 홈 내 현황·관리자 공지·우수 사례 두 단계 공개·크루 둘러보기)를 적용했습니다.

```text

P-12 시연 로그인 [공개] ─ 역할 → 계정 → 시연 로그인 → 언제나 P-01
P-13 이용 가이드 [공개, 관리자 절차는 관리자만] ─ 목차 → 섹션 스크롤

   미션 목록 P-03 → 미션 상세 P-04 ─ [크루장] 퀵 리뷰 열기 → 퀵 리뷰 P-05

알림함 (로그인한 모든 역할, 헤더의 알림 버튼) · 내 성과·내 제안 (크루원, 상단 메뉴)
크루 메뉴 '성과' (크루장): 크루원 성과 · 기록 요청 · 대시보드 탭
운영 관리(관리자): [크루 현황 | 대시보드 | 광고 제안 | 공지] · 개인 상세 › 광고·커머스 제안에서 수익 기록 입력
시연 도구 P-11 (로그인 후): 다른 계정 체험(P-12 경유) · 카카오 알림 미리보기 · 예시 데이터 초기화
```

| --- | --- | --- |
| 비로그인 | 크루 활동(고르면 로그인 안내) · 이용 가이드 · 로그인 | — |
| 크루원 | 크루 활동 · 이용 가이드 · 이름·역할·로그아웃 | 홈 (다음에 할 일) |
| 크루장 | 크루 활동 · 이용 가이드 · 이름·역할·로그아웃 | 홈 (검토를 기다리는 미션) |
| 관리자 | 이용 가이드 · 운영 관리 · 이름·역할·로그아웃 | 홈 (운영 관리 바로가기) |

- 세션(로그인한 계정)·요청 목적지는 메모리에만 둡니다. 업무 데이터 저장 키·형식(`crew-prototype/data`, v3)은 그대로입니다. 이전 버전이 남긴 예시 사용자 저장값(`crew-prototype/session`)은 읽지도 지우지도 않습니다.
- 비로그인으로 보호 화면을 요청하면 내용 없이 로그인 안내를 보여주고, 로그인하면 홈에 `선택했던 기능으로 이동`이 생깁니다. 자동으로 이동하지 않습니다.
- 알림 예시의 `내 피드백 보기`는 받는 사람 계정이 아니면 계정을 바꾸지 않고 로그인 안내로 갑니다. 받는 사람으로 로그인하면 홈에 `선택했던 피드백 보기`가 보입니다.
- 주소창 경로와는 연결하지 않은 화면 상태입니다(직접 URL 진입·브라우저 뒤로가기 미지원).
- 768px 미만: 로고 + 로그인(또는 시연 도구) + `메뉴` 버튼 → 같은 항목을 세로로 펼칩니다.
- 2단계 화면 기준: 크루 홈(카테고리·소개·최근 미션 카드, 공지는 있을 때만) / 미션 목록(크루장 표: 제출 형식 열·목표 한 줄, 크루원 카드: 목표 요약) / 크루원 미션 상세(다음 행동 → 목표·기준 → 제출 입력 → 이력) / 크루장 미션 상세(현황·퀵 리뷰 열기 → 대상자·상태 요약 → 목표·기준) / 퀵 리뷰(검토 대기 건수, 1440px 폭) / 미션 등록(크루 고정 표시).
- 3단계 화면 기준 (사용자 확정): P-07은 미션 상세의 하위 독립 페이지(게시 정보·성과·회고를 나눠 저장, 입력 출처 수동, 과거 확인일별 기록). P-09 제목은 `전체 크루` 유지, 합계는 한 줄 식 + 막대(안 B), 크루 표는 카테고리·대상·상태 숫자 열, 구성원 목록은 같은 페이지 아래(제안 건수 열 없음). P-10 탭 `광고·커머스 제안`·버튼 `제안 기록 추가` 유지. 관리자 집계 범위(권한)는 그대로 담당 크루이며, 예시 관리자는 모든 크루를 담당합니다. 세부 권한 설계는 후속.
- 4단계 (사용자 확정): '소통' → '커뮤니티'. 목록에서 글을 고르면 목록 자리에 글 상세(`목록으로`), `글 작성` 하나에서 글 구분 선택(크루장 공지·글·질문, 크루원 글·질문). 공지가 위, 나머지는 최신순. 홈 소개 문구 아래의 이용 가이드 버튼은 없앴습니다(헤더 메뉴·아래 안내 구역에 남음).
- 4.5단계 (사용자 확정): 결정 내용은 [디자인 결정](docs/v06/DESIGN_DECISIONS.md) 끝 표. 저장 형식은 v4(우수 사례·알림 읽음 시각 추가)이며 v3 저장값은 처음 저장 직전에 `crew-prototype/backup-v3`로 한 번 백업합니다. 이미 쓰던 브라우저에는 예시 우수 사례·예시 제안이 없으니 `예시 데이터 초기화` 후 확인하세요.
- 6-B (광고 제안, 사용자 확정): 운영 관리 › 제안 탭에서 보내고, 크루원 '내 제안'·크루장 '받은 제안'에서 수락·거절. [디자인 결정](docs/v06/DESIGN_DECISIONS.md) 6-B 표. 저장 형식 v7.
- UI 개선 A (사용자 확정): 주 버튼 로고 주황 + 흰 글자(헤더 로그인·포스터 버튼은 검정), 한 화면에 주황 버튼 하나, 설명 문장은 제목 옆 (?) 도움말로.
- 6-C 후속 (사용자 확정): 커뮤니티 공지 탭([운영 공지]·[크루장 공지] 머리표, 운영 공지는 읽기 전용), 크루장 대시보드는 조회수 합계 추이 대신 미션별 성과·피드백 효과.
- 6-C (사용자 확정): 크루방 카드, 로그인 홈 '내 현황'과 `크루방으로`, 운영 관리 › 공지, 우수 사례 두 단계 공개(성과 한 줄·학습 포인트·크리에이터 동의), 공개 홈 크루 둘러보기. 저장 형식 v8.
- 홈 포스터·커뮤니티 (사용자 확정): 새로 그린 포스터(일반 웹판·모바일 세로판), 커뮤니티 안에 자유게시판·Q&A게시판 탭.
- 6-B 보완 (사용자 확정): 제목 '운영 관리', 확인할 것 카드 4개, 크루 표 합계 행·검색·정렬, 단위는 화면 기준(여러 미션 = 미션 배정 건, 미션 하나 = 대상 명), 받는 사람은 크루별로 펼쳐 고르기.
- 6-A (첫 테스터 피드백, 사용자 확정): [디자인 결정](docs/v06/DESIGN_DECISIONS.md) 6-A 표. 저장 형식 v6.
- 5단계 (사용자 확정): [디자인 결정](docs/v06/DESIGN_DECISIONS.md) 끝 표. 저장 형식 v5(수익 기록·기록 요청 추가, v4 원래 값은 `crew-prototype/backup-v4`로 백업). 수익 기록은 기록용이며 정산이 아닙니다.
- 알림 예시는 크루원도 본인이 받은 피드백 알림만 볼 수 있고, 같은 계정이면 바로 해당 미션 피드백을 엽니다. 미제출 안내는 크루장·관리자만 봅니다.

## 시연 순서 예 (T-02~05)

계정 바꾸기: 처음엔 헤더 `로그인`, 로그인 뒤에는 시연 도구 › `다른 계정 체험` → 역할·계정 → `시연 로그인` (언제나 홈에 도착).

1. **민지**로 로그인 → 홈 `다음에 할 일`의 `미션 보기` → `제출하기` (검토 대기 2·보완 0·완료 1·미제출 2)
2. **지훈** → 홈 `검토를 기다리는 미션`의 `미션 보기` → `퀵 리뷰 열기` → 민지 → `보완 요청` + 수정 방향 → `보완 요청 남기기`
3. 시연 도구 › 알림 예시 → `내 피드백 보기` → 로그인 안내 → **민지**로 로그인 → 홈 `선택했던 피드백 보기` → `수정본 제출하기`
4. **지훈** → 크루 활동 › 미션 → 미션명 → `퀵 리뷰 열기` → `완료 처리` → `남은 검토 대기 없음`
5. **민지** → 크루 활동 › 미션 → 완료된 미션 `미션 보기` → `게시 기록 남기기`(게시·성과 페이지) → `게시 정보 저장` → 성과·회고에서 확인일·조회수 `성과 기록 저장` (조회수를 비우면 미집계, 0을 넣으면 0회)
6. **서연(관리자)** → 홈 → 운영 관리 › 크루 현황에서 확인할 것 카드와 크루 표 합계 행 `미션 배정 5건 · 검토 대기 1 · 보완 요청 0 · 완료 2 · 미제출 2` 확인 → 푸드 A 행 → 아래 구성원 표에서 민지 `개인 보기` → 콘텐츠 성과·광고·커머스 제안 탭
7. **지훈** → 크루 활동 › 커뮤니티 → `글 작성`에서 공지를 골라 올리고 관련 미션 연결 → **하늘**(비대상)로 바꾸면 ‘대상자 전용 미션’ 잠금 표시
8. **지훈** → 미션 상세 `미제출 안내 미리보기 (시연)` → `미제출 안내 미리보기`
9. `예시 데이터 초기화`로 처음 상태(1/0/1/3)로 되돌림

## 구현 메모·가정

- 저장 흐름: 명령이 다음 데이터 전체를 계산 → localStorage에 저장 → 성공하면 화면·알림 확정. 실패하면 이전 상태와 입력을 유지하고 오류 띠를 띄웁니다. 저장 중 상태가 보이도록 300ms 대기를 둡니다(`SAVE_DELAY_MS`).
- 중복 방지: 버튼 disabled + 처리 중 가드 + 도메인 조건(최신 검토 대기 버전만 처리, 검토 대기·완료 상태에서 제출 불가, 피드백 이벤트당 알림 1개).
- 마감 일시는 `datetime-local` 값을 Asia/Seoul로 해석하며, 지금보다 이전 일시로는 새 미션을 등록할 수 없게 했습니다(제작 가정).
- 시연 로그인은 고른 역할과 계정 기록의 역할이 같을 때만 됩니다. 역할을 바꾸면 계정 선택이 풀립니다.
- 메뉴 숨김 외에 화면 이동·렌더링마다 예시 접근 범위를 확인합니다. 실제 서버 보안이 아닙니다.
- 화면 세부(헤더·메뉴·목록 행·버전 상자·피드백 입력·알림 문구)는 `docs/preview.html` 견본에 맞췄습니다. 견본의 고정 숫자는 쓰지 않고 모두 원본 데이터에서 계산합니다.
- 색은 [v0.6 디자인 결정](docs/v06/DESIGN_DECISIONS.md)을 따릅니다: 주 버튼 무채색, 로고 주황 `#FF6E00`은 브랜드 영역에만.
- 2차 묶음 가정: 게시 URL이 그 결과물의 검토용 공유 링크와 같으면 받지 않습니다. 게시 정보는 고칠 수 있지만, 이미 남긴 확인일보다 늦은 게시일로는 바꿀 수 없습니다. 제안의 내부 메모는 등록할 때만 입력합니다.
- 구조 개편은 화면·이동만 바꿨습니다. 저장 키(`crew-prototype/data`)는 그대로이고(형식은 4.5단계에서 v4로 추가 확장), 저장된 기록은 지우거나 바꾸지 않습니다. 디자인 토큰에는 콘텐츠 폭 두 개(`--content-max` 1200px, `--reading-max` 840px)만 더했습니다.
- 저장 형식은 v3입니다. 이전 묶음에서 저장한 기록(v1·v2)은 지우지 않고 그대로 읽어 새 기록 칸만 더합니다.
- 3차 묶음 가정: 관리자는 크루 소통 메뉴가 없습니다(명세 SC-05 사용자는 크루장·크루원). 미제출 안내 미리보기는 계산만 하고 저장하지 않습니다. 크루 소통 화면의 주황 버튼은 `글 쓰기`/`질문 쓰기` → `올리기` 흐름 하나이고, `댓글 달기`는 보조 버튼입니다.
