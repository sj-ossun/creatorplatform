# 크리에이터 크루 플랫폼 — 프로토타입 (1·2·3차 묶음)

진행자 동반 사용자 테스트용 프로토타입입니다. 기준 문서는 `docs/`에 있습니다.

- 기능 기준: [docs/prototype-spec.md](docs/prototype-spec.md) (기능 명세서 v0.3)
- 화면 기준: [docs/design-system.md](docs/design-system.md) (디자인 시스템 v0.4), [src/styles/tokens.css](src/styles/tokens.css)
- **현재 제작 기준: [docs/CREW_BUILD_BRIEF_v04.md](docs/CREW_BUILD_BRIEF_v04.md) (v0.4 통합본)** — 이하 문서는 이력 보관용: [UI_STRUCTURE_v02](docs/UI_STRUCTURE_v02.md), [UI_STRUCTURE_v01](docs/UI_STRUCTURE_v01.md) · [docs/IMPLEMENTATION_PROMPT.md](docs/IMPLEMENTATION_PROMPT.md)
- 정적 견본: [docs/preview.html](docs/preview.html) + [docs/preview.css](docs/preview.css) (`docs/tokens.css`와 같은 폴더에서 열기)
- 참고: [docs/references.md](docs/references.md), [docs/README.md](docs/README.md)

> 서버·로그인·실제 발송이 없습니다. 모든 데이터는 같은 브라우저의 localStorage에만 저장되고, 등장인물은 가상 인물입니다.

## 실행

```bash
npm install
npm run dev        # 개발 실행 http://localhost:5173 (포트 고정: localStorage는 출처별로 따로 저장됨)
npm run typecheck  # TypeScript 타입 검사
npm test           # Vitest 핵심 규칙 테스트
npm run build      # 타입 검사 + 배포 파일 빌드 (dist/)
```

설치 없이 링크로 나눌 단일 HTML 파일 만들기 (JS·CSS·글꼴을 한 파일에 포함):

```bash
npm run build:artifact   # → dist-artifact/crew-prototype.html
```

브라우저 시나리오 점검(선택, Playwright가 설치된 환경):

```bash
npm run build && npx vite preview --port 4173 --strictPort
NODE_PATH=$(npm root -g) npm run e2e   # 다른 터미널에서
```

## 화면 구조 (제작 기준 v0.4)

현재 제작 기준은 [docs/CREW_BUILD_BRIEF_v04.md](docs/CREW_BUILD_BRIEF_v04.md)입니다. 업무 규칙은 02, 전체 구조는 01, 작업 내부 표현은 03을 따릅니다. 이전 UI_STRUCTURE v0.1·v0.2와 '승인된 화면 배치 유지' 지시는 이력으로만 보관합니다.

```text
서비스 홈 P-01 ─ 할 일 → 미션 상세 / 검토하기 → 퀵 리뷰
   └ 내 크루 → 크루 홈 P-02 ─ 크루 메뉴: 크루 홈 · 미션 · 소통
                 미션 목록 P-03 → 미션 상세 P-04 ─ [크루장] 퀵 리뷰 열기 → 퀵 리뷰 P-05
                    └ 미션 등록 P-06 → 새 미션의 퀵 리뷰 P-05
                 소통 P-08 → 권한 있는 관련 미션
운영 관리 (관리자) : 전체 크루 P-09 → 구성원 목록 → 개인 상세 P-10
시연 도구 P-11     : 예시 사용자 전환 · 초기화 · 알림 미리보기
```

| 역할 | 전역 메뉴 | 시작 화면 |
| --- | --- | --- |
| 크루원 | 홈 · 내 크루 | 서비스 홈 (이번에 할 일) |
| 크루장 | 홈 · 내 크루 | 서비스 홈 (검토할 미션) |
| 관리자 | 운영 관리 | 전체 크루 |

- 퀵 리뷰는 특정 미션에 속한 작업 페이지입니다. 위치 표시 `크루 / 미션 목록 / 미션 / 퀵 리뷰`와 `미션 상세로 돌아가기`가 있고, 목록·상세 병렬 배치는 이 페이지에서만 씁니다.
- 크루원 미션 상세는 목록 패널 없이 독립된 단일 본문입니다.
- 알림 미리보기(피드백 도착·미제출 안내)는 시연 도구 안에서 엽니다. 크루장 미션 상세에도 `미제출 안내 미리보기 (시연)` 연결이 있습니다.
- 미션 목록 필터(조회용): 크루원 전체 / 내 할 일 / 완료, 크루장 전체 / 검토할 미션. 상세에서 돌아와도 유지되고 예시 사용자가 바뀌면 해제됩니다.

## 시연 순서 예 (T-02~05)

1. 시연 도구에서 예시 사용자 **민지** → 홈 `제출하러 가기` → `제출하기` (검토 대기 2·보완 0·완료 1·미제출 2)
2. **지훈** → 홈 `검토하기`(퀵 리뷰) → 민지 → `보완 요청` + 수정 방향 → `보완 요청 남기기`
3. 시연 도구 › 알림 미리보기 → `내 피드백 보기` (예시 사용자가 민지로 바뀜) → `수정본 제출하기`
4. **지훈** → 내 크루 › 미션 → 미션명 → `퀵 리뷰 열기` → `완료 처리` → `남은 검토 대기 없음`
5. **민지** → 내 크루 › 미션 → 완료된 미션 `미션 보기` → `게시 기록 남기기` → 플랫폼·게시 URL·게시일 저장 (조회수를 비우면 미집계, 0을 넣으면 0회)
6. **서연(관리자)** → 운영 관리(전체 크루) 집계 1/0/2/2 확인 → `구성원 보기` → 구성원 표에서 민지 → 콘텐츠 성과·광고·커머스 제안 탭
7. **지훈** → 내 크루 › 소통 → `글 쓰기`로 공지를 올리고 관련 미션 연결 → **하늘**(비대상)로 바꾸면 ‘대상자 전용 미션’ 잠금 표시
8. **지훈** → 미션 상세 `미제출 안내 미리보기 (시연)` → `미제출 안내 미리보기`
9. `예시 데이터 초기화`로 처음 상태(1/0/1/3)로 되돌림

## 구조

```
src/
  domain/      타입, 상태 코드, 업무 명령(계산만), 집계, 접근 범위, 한국 시간 처리
  storage/     localStorage 어댑터 (schemaVersion, 이 앱 키만 사용)
  state/       Context 공유 상태, 저장 성공 후 확정(commit.ts), 화면 이동·접근 확인(routes.ts)
  data/        예시 데이터 (최초 실행·초기화에서만 생성)
  components/  디자인 시스템 6장 컴포넌트 (CSS Modules, 토큰만 사용)
  features/    화면(SC-01·02·03·08)과 2차 안내
e2e/           브라우저 시나리오 점검 스크립트
```

## 구현 메모·가정

- 저장 흐름: 명령이 다음 데이터 전체를 계산 → localStorage에 저장 → 성공하면 화면·알림 확정. 실패하면 이전 상태와 입력을 유지하고 오류 띠를 띄웁니다. 저장 중 상태가 보이도록 300ms 대기를 둡니다(`SAVE_DELAY_MS`).
- 중복 방지: 버튼 disabled + 처리 중 가드 + 도메인 조건(최신 검토 대기 버전만 처리, 검토 대기·완료 상태에서 제출 불가, 피드백 이벤트당 알림 1개).
- 마감 일시는 `datetime-local` 값을 Asia/Seoul로 해석하며, 지금보다 이전 일시로는 새 미션을 등록할 수 없게 했습니다(제작 가정).
- 역할 선택을 바꾸면 그 역할의 첫 예시 사용자로 바뀝니다. 역할과 사용자가 어긋난 상태는 만들지 않습니다.
- 메뉴 숨김 외에 화면 이동·렌더링마다 예시 접근 범위를 확인합니다. 실제 서버 보안이 아닙니다.
- 화면 세부(헤더·메뉴·목록 행·버전 상자·피드백 입력·알림 문구)는 `docs/preview.html` 견본에 맞췄습니다. 견본의 고정 숫자는 쓰지 않고 모두 원본 데이터에서 계산합니다.
- 회사 공식 주황 HEX는 미확정이며 `#FF7A00`을 제작값으로 씁니다.
- 2차 묶음 가정: 게시 URL이 그 결과물의 검토용 공유 링크와 같으면 받지 않습니다. 게시 정보는 고칠 수 있지만, 이미 남긴 확인일보다 늦은 게시일로는 바꿀 수 없습니다. 제안의 내부 메모는 등록할 때만 입력합니다.
- 구조 개편은 화면·이동만 바꿨습니다. 저장 키(`crew-prototype/data`)와 schemaVersion(3)은 그대로이고, 저장된 기록은 지우거나 바꾸지 않습니다. 디자인 토큰에는 콘텐츠 폭 두 개(`--content-max` 1200px, `--reading-max` 840px)만 더했습니다.
- 저장 형식은 v3입니다. 이전 묶음에서 저장한 기록(v1·v2)은 지우지 않고 그대로 읽어 새 기록 칸만 더합니다.
- 3차 묶음 가정: 관리자는 크루 소통 메뉴가 없습니다(명세 SC-05 사용자는 크루장·크루원). 미제출 안내 미리보기는 계산만 하고 저장하지 않습니다. 크루 소통 화면의 주황 버튼은 `글 쓰기`/`질문 쓰기` → `올리기` 흐름 하나이고, `댓글 달기`는 보조 버튼입니다.
